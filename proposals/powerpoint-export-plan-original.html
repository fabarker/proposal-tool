The recommended design

Generate the Excel workbook once, render its approved print pages, and place those pages in a PowerPoint with native, editable headings, subheadings and footnotes.

This is the strongest route to the requested visual fidelity. The PowerPoint table regions are rendered pictures of the Excel report. They retain the report’s fonts, fills, borders, number strings, cell geometry and resolved conditional formatting. The tables and charts are not individually editable PowerPoint objects. The Excel workbook remains the editable tabular source. That distinction is part of this proposal, not an implementation detail to discover after launch.

“Exactly the same” needs a defined reference. No independent spreadsheet renderer can be assumed to match every desktop version of Excel. Qualify one pinned renderer against approved Excel print output before implementation proceeds past the fidelity spike. If any table or chart differs, the strict parity requirement has not been met. A shared data model alone cannot establish visual parity.

Use Python report definitions and openpyxl for XLSX, a qualified local workbook renderer, and python-pptx for the PPTX container and slide text. This is a proposal for the product’s Python implementation, not a new web stack or a Django migration.

Technical basis: python-pptx’s table model exposes text, cells and merges. It is a different rendering model from Excel. Aspose.Cells documents per-page worksheet rendering. Neither fact proves that a particular workbook will render identically.

Important details that the summary alone would miss

  • includeFees=False removes two columns: “Mgmt fee” and “Wtd fee (bp)”. Product Cost remains. The implementation has 13 columns with fees and 11 without (implColumns, lines 97–125). Some comments still describe three removed columns; the executed code is the authority.
  • The current strategic table includes Volatility, as well as Estimated Mean Return and Sharpe Ratio. Its categories use bold navy text and rules on white, unlike the older golden workbook’s blue bands (lines 752–835).
  • The current risk sheet has 16-point rows, paired Nominal/Real columns, and merged summary values. VaR/CVaR reversal is driven by kind == "loss", not by taking an absolute value of every field (lines 979–985).

Move report semantics, style definitions and layout decisions into a pure Python report model. Keep Excel-specific serialization in an adapter. For the recommended fidelity route, PowerPoint consumes the resulting workbook’s rendered pages, so no PowerPoint table theme can drift from Excel. The refactor makes the style system explicit and prepares an editable adapter later; rendering the workbook itself already provides the essential visual synchronization.

Numerical invariants that must survive the refactor

buildImplementationRows() already centralizes Python implementation arithmetic. Preserve it first, then optionally relocate it behind a compatibility import. Weights close to 100.00% by largest remainder across the entire product table. Notional is rounded to the nearest 100 using the existing Python expression, and weighted fee in bp is (productCost + managementFee) × printedPct. Category values and the total aggregate these printed lines. Preserve ordering and tie-breaking, combined private-asset sleeves, base-specific sleeve editions, tactical tilt and volatility-premium funding, and zero-weight filtering.

On portfolios, a category’s 34% is stored as 0.34 with 0.0%, while its asset’s 34 percentage points are stored as 34 with 0.0. On risk rows, percentage-point payloads become fractions. On assumptions, percentage values already arrive as fractions. VaR/CVaR use the loss-kind sign reversal only; probabilities retain their sign. A shared numeric type/format contract prevents double scaling and double negation.

One proposal identity across formats

A new UID is currently minted for every Excel click. Introduce a bundle identity for the new two-format flow: the first export freezes the complete snapshot and stores the generated XLSX. A subsequent format download for that same frozen proposal uses its stored workbook and manifest, not a fresh analytics or fee lookup. A scenario edit starts a new proposal snapshot and UID.

Persist an idempotency key and a scoped association between the caller, scenario revision and delivered proposal. Include dependency/report versions in the snapshot fingerprint; revision alone cannot detect a changed fee card or sleeve edition. Reusing a specific UID always means using its archived state, even if the catalogue has since changed. Provide a “Generate updated proposal” action when a refresh is needed. A retry for the same key returns the same artifact and creates no duplicate register proposal.

Register migration: preserve the current proposals.workbook* fields and existing historical rows. Add an append-only proposalArtifacts table keyed by proposal UID, format and artifact version, storing MIME, filename, byte count, hash, bytes, workbook hash and render/report metadata. Store the complete report snapshot/manifest as opaque versioned data associated with the proposal, rather than adding comparison analytics to the register’s searchable allocation fields. Old proposals remain Excel-only unless a faithful historical conversion can be proven.

Refactor proposalRegister.record() so a first-time PPTX request inserts the proposal, XLSX, snapshot and PPTX artifact in one transaction before returning bytes. A later PPTX request atomically appends its artifact to an existing proposal without updating the original record. Validate that the filename, XLSX/PPTX core identifier and manifest carry the same UID. Expose the PPTX download alongside the workbook in the existing admin register using its current access rules, and secure any PWA reuse endpoint with the established authorization policy and caller scoping.

Rendering and operation

Proposed first renderer candidate: a pinned, self-hosted Aspose.Cells for Python via .NET worker, because it documents worksheet rendering by print page. This is a candidate requiring a paid-license and deployment review, not an existing dependency or a proven fidelity solution. Compare it against the current workbook in Excel during the first spike. A pinned LibreOffice headless worker is an alternative to evaluate if licensing is unsuitable, but cannot be treated as an identical renderer without the same comparison.

Run conversion in a bounded worker process, not directly in the async event loop. Give each job an isolated temporary directory/profile, clean it on completion or failure, prevent external-link fetching, and cap runtime, pages, image dimensions and memory. Generate only from the application’s workbook. Cache by workbook SHA-256 plus renderer/font/report versions. For a typical 4–8-page export, measure whether synchronous completion is comfortably inside the current 300-second proxy timeout; if not, use a queued job with 202/status/download endpoints. A long request must not occupy unbounded service threads.

References: Aspose worksheet-to-image pages; LibreOffice headless conversion parameters. Avoid a Windows Excel COM service as the default architecture: Microsoft does not recommend or support ordinary server-side Office automation. An attended Excel reference export for QA is a separate activity.

Verification must cover three distinct kinds of parity

  1. Numerical and structural equality. Compare every raw cell value, scale, number format, font, fill, per-edge border, merge, alignment, row height, column width, formula if any, conditional rule and print setting against a captured production baseline. Check row coverage and totals, fee exclusions, metadata and chart series. Byte-for-byte XLSX equality is not required because ZIP metadata may differ.
  2. Rendered visual equality. Compare each workbook page from the candidate renderer against the approved Excel reference at the same page size and raster resolution. Require identical displayed text/numbers, colors, border treatment and geometry; inspect difference images for font substitution and chart/legend shifts. If rasterization permits a small antialiasing tolerance, record it explicitly and obtain review acceptance instead of calling it literal pixel identity. Compare each PPTX table region against the exact image embedded in it, accounting only for the declared uniform placement scale.
  3. Change propagation. Change one shared style token, one row height, one number format and one chart color in a test fixture. Both fresh exports must update together; old archived exports must remain unchanged. Check the same snapshot hash, workbook hash and UID in both artifacts.

A chart-only page is valid; never synthesize a misleading data table merely to fill it.
Stress conditional formattingThe two Excel rules use <0 and >0 with font colors #9C0006 and #006100. The renderer must evaluate them. Check raw values before display rounding, including a tiny negative value that prints “0.0%”. Exact zero stays the base color. Native PPTX cannot retain the live Excel rule behavior.
Number formats, dates and currencyRendered pages retain Excel strings. A native adapter must implement the approved small format catalog and locale rules. Preserve $#,##0 even where the proposal currency differs; flag the current literal rather than silently correcting only the deck. Maintain spaces/indents and blank/zero distinctions.
Print pages are not defined todayExplicitly review paper/margins/bounds/breaks in the first phase. Changing print metadata or repeated headers changes the current print presentation and requires review as part of this feature. Do not claim the six mock-ups reproduce today’s automatic page breaks.
1:1 physical size and projection readabilityA scaled page is proportionally identical, not the same physical font size. Use one declared scale, test a minimum readable size, and prefer more pages or a custom canvas over clipping. Dense 13-column tables will remain dense. Eight slides is a typical target, not a license to omit content.
Protection and subsequent editsKeep existing Excel protection, including hidden chart data. It is not encryption. PowerPoint has no equivalent Excel cell-lock behavior; images can still be moved/deleted. Do not promise tamper resistance. The archived hash and exact delivered bytes remain the record.
Data provenance and misleading labelsRetain the 2.5% risk-free assumption in the assumptions header and identify modelling windows. Show analytics currency where it differs. Preserve adapter-provided report names for parity; any normalization of stale baked labels must be a separate shared change affecting both outputs.
Snapshot drift, archive reconstruction and retriesFreeze dependencies, results and page/copy metadata once. Reuse archived workbook bytes. Store new PPTX artifacts append-only and make requests idempotent. Historical register JSON alone omits analytics/comparisons, so it cannot regenerate equivalent slides.
Worker cost and accessibilityBenchmark image DPI, PPTX size and storage growth before release. Use lossless images, bounded jobs and cache hashes. Provide meaningful alt text and a structured text summary in speaker notes from the same snapshot, with Excel available for cell-level access. Raster tables are less accessible and not searchable as native cell text.
