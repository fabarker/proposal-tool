Proposal · Repository · for review · revised

The sleeve library decides which allocations each implementation type offers; the private-markets funding split moves into the repository

A book is offered under an implementation type when, and only when, that type's library holds a sleeve for every category the book holds. There is no second list to maintain: to stop offering Full books under ESG, the desk archives ESG's Hedge Funds sleeves, and to offer them again, adds one back. Separately, the split that holds a private-markets commitment until capital is called becomes a repository setting instead of a constant in code.

1 · Summary

Offered = buildable from the library decided

An allocation is offered under an implementation type only if every category it holds has a sleeve in that type's library. That takes edition rules into account and leaves out broken and archived sleeves. It is worked out, never entered: there is no allow-list anywhere, and the code table that does this job today (D49) is deleted.

When a book isn't offered, the PWA is told which category has no sleeve under which type. The desk sees the same thing, per type, in a read-only view in the Repository, and the sleeve editor warns before any change that would withdraw books.

The funding split, in the repository

The destinations and their parts, today 1 part Investment Grade Fixed Income to 2 parts Public Equity, become a Repository setting with notes, history and restore. A destination must be a category every private-markets book holds.

A change applies to scenarios still in progress. Delivered proposals keep the split they were delivered with, and the register records which one that was.

One thing to do before switching over. Today's library holds sleeves for every category under every type, Hedge Funds and Private Markets under both Onshore types included. Switched over as it stands, every type would offer all 172 books. §4 sets out the curation that keeps today's offer exactly, and the plan makes the switch the last step, after the desk has seen and approved the result.

2 · What happens today

A table in code decides (D49)

rules.VARIANT_ALLOCATIONS lists the allocation types each implementation type offers, and VARIANTS_EXCLUDING_RE forces the real-assets exclusion under ESG. The picker, the schema's availability set, the server-side key check and the pruning of columns on a type change all read it. The library plays no part: a type can hold sleeves the table never lets anyone use.

The funding split is a constant (D136)

rules.PRIVATE_FUNDING is Investment Grade Fixed Income ⅓, Public Equity ⅔. The model reads it in Python and the page reads it from the schema. The workbook, the deck and the register take their figures from the model. Changing it needs a release, and nothing records which split a delivered proposal used.

3 · The rule

The bookEvery category it holds, with Private Equity and Other Private Assets counted as one: the Private Markets sleeve (D60).
+
The type's libraryFor each of those categories, is there a live, unbroken sleeve that serves this book, by an edition whose rules match it or by the fallback?
=
OfferedYes for every category: offered. Otherwise not offered, with the missing categories named.

Exactly what counts

  • Categories: those the book holds with a weight above zero, strategic weights before any toggle. Core needs Hedge Funds; Full and ex-HFs need Private Markets; every book needs Public Equity; everything but All Equity needs both fixed income categories.
  • A sleeve serves a book when the resolver would put it on the rail for that book: an edition whose rules match the book's currency, risk level and allocation type, or else the fallback edition (D89). Archived sleeves don't count. Nor do broken ones, whose product has left the catalogue, since a sleeve that can't be priced is never offered.
  • The two automatic categories (Asset Allocation Strategies and Hybrid Fixed Income) don't decide what is offered. They arrive with the tilt and volatility premium toggles, which already switch themselves off when their fixed sleeve is missing.
  • Worked out for the whole universe (172 books × 4 types) and cached. The cache refreshes when the universe reloads, when any sleeve is saved, archived or restored, and when a new catalogue arrives.

ESG's real-assets rule

Today the code forces ESG's ex-HFs books to exclude real assets. The library can't say this as things stand. A book with real assets and the same book without them need the same Private Markets sleeve, and sleeve edition rules deliberately leave the real-assets exclusion out (D89). There are two ways to go, and decision 1 asks which:

A · Keep it, in the sleeves recommended

Add the real-assets exclusion as a fourth field an edition rule can constrain. ESG's Private Markets sleeve then carries a rule "real assets excluded" and no fallback, so an ESG ex-HFs book with real assets has no Private Markets sleeve and isn't offered. The rule stays with the sleeve and is visible there. It's a small change to sleeveRules, and a restriction the desk can lift by giving the sleeve a fallback edition.

B · Drop it

ESG offers ex-HFs books with and without real assets, wherever its library can build them: 28 more books than today (7 per currency). This is the simplest, if real assets under ESG are acceptable in practice.

4 · Switching over without changing what is offered

To keep today's offer exactly, the desk archives the sleeves the code table has been hiding, before the switch. 6 · What a PWA sees

The picker lists only offered books, as now, but a book that isn't offered says why, and the reason is always a missing sleeve. The PWA can take a specific request to the desk ("US Onshore has no Hedge Funds sleeve") instead of "it's greyed out". The reasons come in the schema beside the availability set, so the page never works them out itself. This mock-up reads the library from the console above.

    When the library changes under a scenario

    A scenario built before a change keeps its columns, and nothing is removed from under the PWA. On opening it they see a notice: "USD Moderate Full is no longer offered under US Onshore: its Hedge Funds sleeves were archived on 3 Oct". The export is refused until the base is changed, just as it is today for a missing sleeve or a below-minimum position. Delivered proposals are never touched: the register holds what was delivered. The same applies when a new catalogue breaks a type's only sleeve for a category, in which case the Repository header also flags the withdrawal.

    7 · The private-markets funding split

    This is the second view of the Rules tab. The split is a short list of destination categories, each with a number of parts. The shares are the parts over their total, so "1 and 2" is exactly ⅓ and ⅔, with no 33.33% and 66.67% that fail to add up. Everything downstream already takes the split as data (D136): the model, the page's mirror, the workbook, the deck and the Initial Allocation sheet and slide all follow it without code changes. The page's wording handles thirds and falls back to percentages, and the deck's words ("a third", "two thirds", "half") do the same.

    What the console enforces

    • A destination must be held by every private-markets book. Otherwise some books would have nowhere to put the money. The console checks each category against the universe: Investment Grade Fixed Income, Other Fixed Income and Public Equity are held by all 112 private-markets books; Hedge Funds by only 56, so it is refused, with that count shown.
    • Between one and three destinations, each once, each with parts greater than zero. Private Equity and Other Private Assets can't be destinations.
    • Money still goes to the sleeves chosen for each destination, split in their own proportions, as it does today. That includes the tilt case, where Investment Grade Fixed Income is emptied by the tilt (D136).

        8 · Data, API and audit

        What is offered: no new data

        There is nothing to store. The offer is worked out from the sleeves, their edition rules and the catalogue, all of which already have history, notes, archive and restore (D57, D65, D89). The audit trail for "why was Full withdrawn under ESG?" is the sleeve history that archived its Hedge Funds sleeves, and the Activity feed now says what each sleeve change did to the offer ("withdrew 84 books from PMG ESG"). If decision 1 goes to A, sleeveRules gains a fourth field, realAssets (excluded or held), under the same validation and overlap checks as the other three.

        The funding split: a small store

        policies        kind ('funding'), scope ('*' for the house split, or an implementation type),
                body (JSON: destinations and parts), revision, updatedBy, updatedAt
policyHistory   one append-only row per revision: kind, scope, revision, action, body, note, actor, at

        These go in the repository's own SQLite file, beside the sleeves, as schema revision 4. On first open they are seeded from today's constant with a "baseline" revision, so an upgrade changes nothing. History is append-only as for sleeves: restoring adds a revision. Changes show in Activity. The rows export and import through sleeveTools (--policies).

        The schema the page already fetches keeps its shape: availability narrows as before and gains unavailableReasons; rules.privateFunding is served from the store rather than the constant and gains its revision. options.variantAllocations stays for compatibility, derived from the offer.

        Porting to Cyrus

        This is the usual shape: re-copy the package and the page folder, and paste the router block, which gains six routes. There is no configuration. One thing is not a plain copy: curate the host's library before deploying the switch, since the host's library, not the packaged one, decides what the host offers. The read-only Offer view ships a phase earlier, so the curation can be done and checked in place. The porting guide gains a step for this, and a check that each type offers the counts the desk expects.

        9 · Plan

        There are four phases, each shippable on its own and each leaving the tool working. The switch that lets the library decide comes last, after the desk has seen the Offer view and curated the library, so no PWA ever sees the offer widen by accident.

        1. The funding split in the repository

          • Schema revision 4 with the two tables, seeded 1:2. The store, the endpoints, history and restore, and the console's Private markets funding view with its validation and preview.
          • initialLines and the schema read the store. The register records the split's revision.
          • Tests: the seeded split reproduces today's figures exactly (the live scenario's 87.9bp against 98.6bp, the golden 93.0bp); a 1:1 split moves the initial model; Hedge Funds is refused as a destination; the page's JavaScript and the Python still agree when given a non-default split; the register stamps the revision.

        2. The Offer view and the sleeve editor's warning (read-only; nothing changes for PWAs)

          • The offer computation and its cache. The Rules tab's Offer view, with the "differs from today" marks, and the offer endpoints.
          • The sleeve editor warns before a save, archive or rule change that would withdraw books, and Activity records each change's effect on the offer.
          • If decision 1 is A: the realAssets rule field for editions.
          • Tests: removing a category's sleeves withdraws exactly the books that hold it; editions, fallbacks, archived and broken sleeves are handled as the rail handles them; the cache refreshes on sleeve saves and catalogue loads; the warning counts are right.

        3. The desk curates the library

          • Archive the Hedge Funds sleeves under ESG and both Onshore types, and the Private Markets sleeves under both Onshore types. Under decision 1 A, give ESG's Private Markets sleeves the rule "real assets excluded".
          • The Offer view then shows no marks against today: 172, 60, 32 and 32. This is desk work in the console, with no code change, and in Cyrus it is done in Cyrus.

        4. The library decides

          • The schema, validateKey, the type-change pruning and the export gate read the offer. The picker shows the reasons, and scenarios whose base drops out show the notice and are refused at export.
          • VARIANT_ALLOCATIONS and VARIANTS_EXCLUDING_RE are deleted.
          • Tests: with the curated library, the offer matches today's exactly (172, 60, 32 and 32 books); archiving and restoring a sleeve withdraws and restores its books in the picker; a 422 names the missing category; the reasons are served and shown.

        Each phase gets its own entry in DEVIATIONS.md and a porting-guide update, as usual.

        10 · Decisions

        Decided: the library alone decides what is offered

        A book is offered under an implementation type exactly when that type's library has a sleeve for every category it holds. There is no allow-list, and the D49 table is removed.

        1. ESG's real-assets rule

        Keep it, by letting a sleeve edition's rules say "real assets excluded" (ESG then offers 60 books, as today), or drop it (ESG offers 88, adding ex-HFs books with real assets).

        Recommended: keep it, in the sleeves (A). It stays sleeves-driven and visible on the sleeve itself, and the desk can lift it later by adding a fallback edition.

        2. A scenario whose base stops being offered

        Leave it open and deliverable, block its export, or remove the column.

        Recommended: keep it open with a notice naming the sleeve change, and refuse export until the base is changed.

        3. One funding split, or one per implementation type?

        The destinations are categories; the products come from each type's own sleeves, so ESG already parks in ESG products. A per-type override is only needed if a type should park in different categories or proportions.

        Recommended: one house split, with per-type overrides available but none set.

        4. Which categories can receive the parked money?

        Only categories every private-markets book holds (today Investment Grade FI, Other FI and Public Equity), or any category, with the share going pro rata to the others where a book lacks it.

        Recommended: only categories every private-markets book holds.

        5. Does a split change reach scenarios in progress?

        Immediately, as a new fee card does, or only for scenarios created after the change.

        Recommended: immediately. Delivered proposals never change, and the register records the revision each used.

        Figures: 172 strategic books (43 per currency); 112 of them hold private markets. Library counts are the packaged sleeve library's live sleeves per type and category.
