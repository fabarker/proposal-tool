Ten ways to create a sleeve

The New sleeve form as it is today, what makes it hard, and ten redesigns built on your live library: 4 implementation types, 7 categories, 101 sleeves and the 73 products in the catalogue, read from the repository without changing it. Option 11 combines 4 and 5. Every mock-up works end to end: choose where the sleeve goes, name it, add products, set weights and create it. Creating is simulated in the page and resets when you start again. Press Choose on the one you want.

What's hard today

The New sleeve form in the D156 console, opened from the category tiles and from the table, at 1600px and 1280px. Nothing was saved while taking these.

  • 1Where it goes is decided for you. Opened from the tiles, the form starts in the first category with room, and the breadcrumb then claims you chose it. The category is a dropdown in the corner, after the name.
  • 2Editions come before products. An advanced choice nobody makes on a first sleeve (none of the 101 live sleeves has an edition) takes a label field, a paragraph of help and a full-width "+ Add a rule" bar, all above what the sleeve holds.
  • 3Products come last and start empty. The table says "no products yet" above a full-width "+ Add product" bar; cost and minimum show only as small grey text inside the picker, and not at all once a product is chosen.
  • 4Create is disabled without saying why. "No changes yet", then one problem at a time in the bar. Nothing lists what is still missing, and the button never says what it will create.
  • 5What will be created is in the smallest text on screen. "will be created under PMG Multi-Asset Portfolio" is an 11px grey line at the foot of the form.
  • 6Unavailable implementation types only explain themselves in a tooltip. A type that already has a sleeve of that name, or whose fixed category is full, is a greyed checkbox; the reason is a title attribute that keyboard and touch users never see.
  • 7A name that already exists turns the new sleeve into an edition. Typing "Passive" in Public Equity leaves the type ticked but greyed, and the only message is "Passive already has a fallback edition; give this one rules and a label" - which reads as an instruction to do something you never meant to.
  • 8The picker is a long unfiltered list. All 73 products, with facts and cost in 13px grey; nothing narrows it to what this category's sleeves already use.
  • 9A bad weight is reported far from the field. "1,5" outlines the box red and the total reads 0.00; the explanation ("not a plain number") is only in the bar at the top of the page.

What every option keeps

  • Choose the category, and one or more implementation types (one sleeve created per type)
  • Types that cannot take the sleeve shown with the reason in visible text: a full fixed category, or a sleeve of that name already there
  • A name of up to 80 characters; the same name under other types explained (they are offered as one sleeve)
  • Products from the catalogue, with asset class, vehicle, style, liquidity, cost and minimum
  • Weights as plain numbers above zero, totalling exactly 100%
  • An optional note shown to PWAs in the picker
  • Editions: added after creating, from the sleeve's page ("+ Add an edition")
  • Problems in plain words next to the field they belong to
  • A primary button that says what it will create ("Create in 2 implementation types")
  • Cancel asks before throwing entries away; afterwards you land on the new sleeve
