# Deviations, decisions and gaps — Proposal Tool build

Every departure from the hand-off package, in the spec §3.3 format: **what
changed, and why**. Decisions the package invited (caching, sessions, module
layout — brief: "yours, decide and move on") are recorded in the second table;
spec gaps found while building are in the third. Nothing here re-litigates a
decision recorded in DECISIONS.md.

## Deviations from the package (§3.3 format)

| # | What changed | Why |
|---|---|---|
| D1 | `get_context()` in the supplied `portfolio_weights.py` now passes `start_date='30-Nov-1983', end_date='31-Dec-2022'`. | As supplied it could not run: `ContextCreator` defaults both dates to `None`, which `CContext.start_date` cannot parse (`dateutil` TypeError). The window is the canonical case study's (`1. Portfolio Analysis/a. Simple Analysis.py`) and matches the 20221231 base-model pickles the environment loads. |
| D2 | One endpoint added to the §3.4 surface: `PUT /api/scenario/{id}` accepting any subset of `{mandate, basis, sleeves}` (requireEditor; 422 `{error, field}`). | §11.8 requires `GET /api/scenario/{id}` to restore *mandate, basis, columns and sleeves*, but §3.4 lists writes only for columns — a contradiction: without a state write, an edited mandate or attached sleeve cannot survive a refresh. One resource-shaped endpoint fills it, mirroring the DELETE-portfolio pattern. Columns keep their §3.4 endpoints (`POST …/portfolio` upserts, `DELETE …/portfolio/{key}` removes). |
| D3 | Hedging is applied as per-asset FX hedge ratios (`HEDGE_RATIOS_BY_OPTION` in `portfolio_weights.py`, applied via `set_hedging_ratios` inside the cached build) instead of `SAAPortfolio.set_hedging_option()`. | `set_hedging_option` is a dead path in this epsilonPhi snapshot: `PortfolioMgr.get_hedge_ratios_from_hedging_option` references `SAAHedging`, a class that exists nowhere in this repo (production-side code). The ratio path is the working mechanism the estimators respect (verified: hedged 6.53% vs unhedged 6.72% vol on USD Core Mod). Hedged=1.0, Unhedged=0.0, Equity Not Hedged=0.0 on Public Equity / 1.0 elsewhere carry their conventional meanings; **ISG Hedged (0.5 on Public Equity / 1.0 elsewhere) is a stand-in awaiting PMG's house ratios**. Hedging stays a constructor argument and part of the cache key, exactly as §15.1a demands. Swapping to the host's hedging service later changes only this table. |
| D4 | `capabilities()` and `describe()` ride the `GET /api/scenario/schema` response (`capabilities`, `dataInfo` blocks); no endpoints of their own. | The port defines both methods but §3.4 gives them no transport, and the footer needs `describe()` from first render. The schema is fetched on open (§11.1), so both arrive exactly when needed. |
| D5 | The page includes `/static/js/accessGate.js` and `/static/js/globals.js` (absolute paths) at the top of `<body>`. | Host convention (HOST_AUDIT §11 script order) and the BRIEF's auth-gate requirement (“keep … the /api/whoami probe”). The delivered prototype lacked both. Opened from `file://` they 404 harmlessly; the page’s `typeof API_BASE` guard keeps working. |
| D6 | The `.spec` annotation asides ("Semantic palette", "What to look at") and the static demo badges do not ship; the notices strip renders live state instead. (The topbar this originally also covered has since gone entirely — D27.) | §6.2's accepted-exception note is explicit that `.spec` is the annotation layer, toggled off in mpo-ui and "never ships in the product". The static badges were prototype chrome; the wireframe (§7.2) shows the notices as live state. |
| D7 | The fixtures adapter carries environment failure knobs (`SCENARIO_FIXTURES_LATENCY_MS`, `_FAIL`, `_FAIL_SCHEMA`, `_FAIL_SLEEVES`, `_FAIL_EXPORT`). | §4.4 requires every §10 state — including error and timeout — to stay reachable through the fixtures adapter over the real stack. Deterministic knobs are the only way to reach them on demand without poisoning real combinations permanently. Documented in `dashboard.env.defaults`. |
| D8 | Scenario state is a file-backed store (one JSON per scenario, atomic writes, 24h retention), not in-memory. | The host launches pmgService with `--workers 2`; an in-memory store would 404 on whichever worker did not create the scenario. Files are worker-safe and survive restarts. Directory configurable via `SCENARIO_STORE_DIR` (default under the system temp dir). Resolved-portfolio payloads remain an in-process cache — recomputable, so per-worker is correct. |
| D9 | The sleeve library is authored data in `sleeves.py`: the prototype's library minus its Cash category, plus the single Asset Allocation Strategies sleeve (product: Tactical Tilt Fund). | The package supplies no separate sleeve source ("PMG sleeve library — stub: same [nothing, supplied]"), and the prototype's data is the only authored library in the hand-off. Cash is not in the supplied weight universe (§16 item 13); AAS carries exactly one auto-attached sleeve (§2.6). Production replaces this module behind the same function. |
| D10 | `advisors.xlsx` (24 advisors, name + office) is authored and shipped beside `advisors.py`. | The reference adapter is specified as Excel-backed (§4.2 item 7) but no workbook was supplied. The six advisors the prototype named are all present. |
| D11 | `epsilonPhi/core/dataModel/dataSources/vendor/IMF.py`: the WEO release download in `get_region_inflation_forecast` is wrapped in try/except. | The function (mid-migration on this branch) already discards the download's result in favour of the vendored `weo_2026_1.csv`, but still paid for — and intermittently failed on — the network call (`httpx.ReadTimeout` observed twice, killing `resolve_portfolio`). The guard preserves the in-progress structure and makes resolves deterministic offline. |
| D12 | The popover's controls mirror the base tier (Allocation select + the two exclusion tick boxes + Risk level), not the prototype's compound six-variant select. | The spec never enumerates the popover's controls (gap G2). The prototype's compound select predates Q32 ("four plus two tick boxes" beats a compound axis), cannot express ex-TAA comparisons (half the 84-combination space, §2.1 scopes excludeTAA per portfolio), and labels variants inconsistently with §2.3's derived names ("Full" in the picker produced a column headed "Full … ex RE"). Mirroring the base tier keeps every key-entry control identical. |
| D13 | The analytics portfolio is built zero-padded to all 19 codes (`include_zero_weights=True`); the screen payload still comes from held rows only. | Padding changes no number (verified equal to 1e-12) and gives every portfolio an identical asset set, which is what lets `Reporting.get_portfolios_table` union heterogeneous portfolios — its own union-with-zero-fill convention — instead of raising `InvalidIndexError` on duplicate spacer labels. Screen semantics (§2.2 blank/dash) are untouched. |
| D14 | The export workbook drops the `assumptions` sheet `generate_report()` always writes. | Open item 6 records the export as "the three on-screen tables **and nothing else**". Removing the sheet honours that reading; restoring it is one deleted line. |
| D15 | Scenario retention is 24 hours (`SCENARIO_RETENTION_HOURS`), and the 404 message says so. | Open item 8 (retention) is undecided and blocks "only the wording of the message"; a number was needed to write the message. Configuration. |
| D16 | `epsilonPhi/core/estimator/assetReturnEstimator.py` optimised: the per-window normalisation statistic is memoised in a shared `_window_cache`; the discarded `convert_asset_to_currency` call is removed; the beta cache is keyed on `(name, currency, start, end, normalized, model hash)` rather than on `hedging_ratio`. | Profiling put 168s of a 255s cold portfolio in this one function, most of it re-orthogonalising the same factor windows once per asset. The change is performance-only and **bit-identical** — `tests/test_tier0_beta_equivalence.py` re-implements the original verbatim and asserts equality, and live output is unchanged to the digit. See `PERFORMANCE.md`, including the two findings this surfaced for the model owner (`hedging_ratio` has never influenced betas; the currency was missing from the cache key). |
| D17 | A third ScenarioPort, `baked`, serves precomputed results from disk (`bake.py` + `bakedAdapter.py`), selected by `SCENARIO_ADAPTER=baked`. | The tool is a lookup over a closed space — 68 combinations per currency × 4 hedging policies (DECISIONS Q2) — so the analytics can be computed once per data version instead of per request. Cold-start resolve drops from ~97s to ~1ms and the read path needs no database. An unbaked combination falls through to the live adapter (`SCENARIO_BAKED_FALLBACK=1`, the default), so correctness never depends on bake coverage. Configuration, not structure: the port abstraction already existed for exactly this. |
| D18 | With `SCENARIO_BAKED_FALLBACK=0` (no database at all), `build_export` writes the workbook from the baked payloads using this package's writer rather than `Reporting.generate_report()`. | Spec §14.3 specifies `Reporting`, and with a delegate configured the export is still delegated to it — the default. But `Reporting` needs live `SAAPortfolio` objects and therefore a database, which would defeat a database-free deployment. The payload writer produces the same three sheets and the same figures under the §14.3 formatting. Whichever path runs, the implementation sheet and its §8.4 rounding are identical, because both call the same `writeImplementationSheet`. |
| D19 | `dashboardRouter.py` constructs the ScenarioPort at module import (inside `try/except`) rather than on the first request. | So the baked adapter's static-table warm-up overlaps service start instead of landing on the first user — it took the first `get_schema` from 465ms to 31ms. Construction is cheap for all three adapters (epsilonPhi's own setup stays lazy), and a failure is swallowed so a misconfigured adapter surfaces on the request that needs it rather than stopping the router loading. |
| D20 | The workspace ground is now `#FBFCFE`, the landing's colour, instead of the `mpo-ui` canvas `#ECEEF1`. `--bg` carries the new value and the landing reads `var(--bg)` rather than a literal. | Requested. It contradicts §7.1's "held just off the workspace canvas (`--bg`, `#ECEEF1`) so the threshold reads as its own surface" — the two surfaces are now identical, so crossing from landing to workspace no longer changes ground. Recorded because §7.1 states the old values explicitly; it is a token change and reverting is one value in `themes.py`. Panels stay `#FFFFFF` and remain delineated by their `--line-strong` borders, so nothing loses its edge on the lighter ground. |
| D21 | The implementation table's first two columns size to their content instead of the specified 248px, and column 2's sticky offset follows column 1 — measured after each render and published as `--impl-c1`. The allocation and risk row headers size to content too. | Requested ("as wide as the longest name"). §9.3 pins column 1 at 248px and column 2 at `left: 248px`; content-width column 1 makes that offset wrong, so it can no longer be a constant. The 248px value survives as the CSS fallback until the first measurement lands. |
| D22 | Both comparison tables are laid out `table-layout: fixed` from measured widths: every portfolio column exactly equal, capped at 260px and floored at 120px, and `.tblwrap` is `width: fit-content` so the frame follows the table. | Requested. Auto layout cannot promise equal columns — it honours each column's own content minimum, so they land within a few pixels but never equal — and without a cap a single portfolio stretched across the whole document. The consequence is that column widths are now computed at render rather than declared; the sizing pass re-runs on resize and on rail collapse, since the equal share depends on the room the document has. |
| D23 | The base column header reads **Proposed Portfolio**; the derived name is the hover tooltip and the `aria-label`. | Requested. §9.1 specifies a `.b-bind` chip reading "Base" beside the derived name, and §2.3 makes the header the derived name. The portfolio being proposed is what the column is; the comparisons are what it is proposed against. The name is not lost — it reaches assistive tech without a hover, and the rail's built list still shows it with its Base tag. |
| D24 | The Nominal/Real strip moved out of the table header into the body, immediately under the "Predicted Performance Over Stress Periods" band. | Requested. §9.2 puts it in the header, but the Factor Based Risk Analytics section above spans both sub-columns, so a header strip claimed a split that does not begin until the stress periods. §9.2's column arithmetic is otherwise unchanged: rows still occupy n×2+1, the strip n×2. |

## Adapter-side decisions (invited by the brief)

| Area | Decision |
|---|---|
| Caching | Three layers: the loader's own memoised context (per currency) and portfolio (per currency+weights+hedging), plus a finished-payload cache per (currency, hedging, key) in the epsilonPhi adapter. Warm resolves are sub-millisecond, which is what makes rehydrate-after-refresh read as instant under the 200ms rule. |
| Concurrency | One coarse `RLock` serialises epsilonPhi compute (its caches and the mutable, self-memoising `SAAPortfolio` are not demonstrably thread-safe; FastAPI runs sync handlers in a threadpool). Columns are separate HTTP requests, so per-column UI states are unaffected. |
| Lazy setup | `CAppConfig.setup()` (~12–14s) runs on first analytics use, not at service start — a fixtures-configured service never pays it and `/health` is immediate. |
| Sessions | See D8. Scenario ids are `sc_` + 12 hex chars; the id rides the URL via `history.replaceState` (no route — §7.1's one-route constraint holds; host pages already use query deep-links). |
| Error mapping | `ValidationError → 422 {error, field}` · unknown/expired scenario `→ 404 {error}` · `LookupError` from the loader `→ 422` (the availability set should have prevented the selection) · `AnalyticsError` and unexpected engine failures `→ 502 {error}` · auth `→ 401 {loginUrl}` / `403 {error}`. The Flask proxy supplies 502/504 when the service is down/slow. |
| Module layout | Everything transplantable in `pmgService/scenario/`; endpoints as a block in `dashboardRouter.py`; auth through `..core.accessControl` — the host's own seam. |
| Measured performance (the brief: "measure it and record the number") | Full record in `PERFORMANCE.md`. Headline: a cold portfolio was ~255s, is ~97s after the Tier 0 fixes (D16), and is **~1ms served from the bake** (D17). Warm repeats were already <1ms through the payload cache. `CAppConfig.setup()` ≈ 9–14s, once, and only on the live path. Export ≈ 50s warm through `Reporting`. The proxy's 300s timeout covers the worst single live resolve. |
| Analytics data coverage | This database carries currency configs for **USD and GBP only** at dataversion 1; CHF and EUR cannot resolve at all (see `PERFORMANCE.md`). The UI offers four currencies because the supplied weights carry four. Left as-is rather than silently narrowing the option list: which currencies PMG intends to serve is a product decision, and the bake manifest records exactly which are covered. |
| Real premia rows | The full 3×3 grid (VaR, CVaR, PoL × 1M/1Y/3Y), matching `get_var_pol_tbl`'s own layout; the prototype's 6-row subset was placeholder data. The rows are server-supplied, so the UI renders whatever arrives. |

## Spec gaps found while building (§ "record it as a gap")

| # | Gap | What was chosen |
|---|---|---|
| G1 | §3.4 lists no write for the mandate/basis/sleeve state §11.8 says is restored. | D2. |
| G2 | The popover's control set is never enumerated (§7.3 specifies behaviour only), and the prototype contradicts §2.3's naming on it. | D12. |
| G3 | VaR sign: the existing report presents VaR/CVaR as positive magnitudes ("Value at Risk … Over 1 Month"), the specified screen (§7.2 wireframe, prototype) as negatives. | Screen shows negatives per the spec; the workbook keeps `Reporting`'s own convention — the same each-surface-keeps-its-own stance §14.5 takes for the two palettes, to be resolved with PMG alongside open items 1–2. |
| G4 | Pre-base control state: §10.2 specifies the empty document and the ringed tier, but not what the Allocation/Risk selects show before a base exists. | Placeholder "Select…" options; the exclusion tick boxes stay disabled until an allocation is chosen (Exclude RE has no truth value without one); the base builds on the first complete selection. |
| G5 | §10.1 specifies skeleton cells for a loading column alongside ready columns, but not the table body when *no* column has resolved (first ever load). | Six generic unlabelled skeleton rows plus the total/metrics skeleton — the surface stays honest without inventing row labels. |
| G6 | The workbook's portfolios sheet zero-fills categories a variant lacks (its own union-with-zero-fill behaviour), where the screen renders blank (§2.2). | Kept: the report's convention is the report's (Q6 confirmed union-with-zero-fill for it); the screen follows §2.2. Same-document reading holds at the label level — identical names, order and figures. |
| G7 | Stress-period and premia row *sets* can differ between adapters (fixtures: 4 crises; epsilonPhi: 9). | The rows are data-driven end to end (§9.2 "never hardcode the crisis list"); the UI unions labels across ready columns in first-seen order. Both adapters now emit the same nine premia rows, grouped (D25). |
| G8 | §9.1 and §9.3 give the tables' row treatments and column list but no column *widths* beyond the implementation table's two pins, and no guidance on how width should behave as the column count changes. | Columns are sized at render: row headers to content, portfolio columns exactly equal between a 120px floor and a 260px cap (D21, D22). Recorded because it is layout the document does not specify, and because it makes table width a computed property rather than a declared one. |
