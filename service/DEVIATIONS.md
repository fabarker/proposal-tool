# Deviations, decisions and gaps — Proposal Tool build

Every departure from the hand-off package, in the spec §3.3 format: **what
changed, and why**. Decisions the package invited (caching, sessions, module
layout — brief: "yours, decide and move on") are recorded in the second table;
spec gaps found while building are in the third. Nothing here re-litigates a
decision recorded in DECISIONS.md.

## Deviations from the package (§3.3 format)

| # | What changed | Why |
|---|---|---|
| D1 | `get_context()` in the supplied `portfolio_weights.py` now passes `start_date='30-Nov-1983', end_date='31-Dec-2022'`. | As supplied it could not run: `ContextCreator` defaults both dates to `None`, which `CContext.start_date` cannot parse (`dateutil` TypeError). The window is the canonical case study's (`1. Portfolio Analysis/a. Simple Analysis.py`) and matches the 20221231 base-model pickles the environment loads. |
| D2 | One endpoint added to the §3.4 surface: `PUT /api/scenario/{id}` accepting any subset of `{mandate, basis, sleeves}` (requireEditor; 422 `{error, field}`). | §11.8 requires `GET /api/scenario/{id}` to restore *mandate, basis, columns and sleeves*, but §3.4 lists writes only for columns — a contradiction: without a state write, an edited mandate or attached sleeve cannot survive a refresh. One resource-shaped endpoint fills it, mirroring the DELETE-portfolio pattern. Columns keep their §3.4 endpoints (`POST …/portfolio` upserts, `DELETE …/portfolio/{key}` removes). |
| D3 | Hedging is applied as per-asset FX hedge ratios (`HEDGE_RATIOS_BY_OPTION` in `portfolio_weights.py`, applied via `set_hedging_ratios` inside the cached build) instead of `SAAPortfolio.set_hedging_option()`. | `set_hedging_option` is a dead path in this engine snapshot: `PortfolioMgr.get_hedge_ratios_from_hedging_option` references `SAAHedging`, a class that exists nowhere in this repo (production-side code). The ratio path is the working mechanism the estimators respect (verified: hedged 6.53% vs unhedged 6.72% vol on USD Core Mod). Hedged=1.0, Unhedged=0.0, Equity Not Hedged=0.0 on Public Equity / 1.0 elsewhere carry their conventional meanings; **ISG Hedged (0.5 on Public Equity / 1.0 elsewhere) is a stand-in awaiting PMG's house ratios**. Hedging stays a constructor argument and part of the cache key, exactly as §15.1a demands. Swapping to the host's hedging service later changes only this table. |
| D4 | `capabilities()` and `describe()` ride the `GET /api/scenario/schema` response (`capabilities`, `dataInfo` blocks); no endpoints of their own. | The port defines both methods but §3.4 gives them no transport, and the footer needs `describe()` from first render. The schema is fetched on open (§11.1), so both arrive exactly when needed. |
| D5 | The page includes `/static/js/accessGate.js` and `/static/js/globals.js` (absolute paths) at the top of `<body>`. | Host convention (HOST_AUDIT §11 script order) and the BRIEF's auth-gate requirement (“keep … the /api/whoami probe”). The delivered prototype lacked both. Opened from `file://` they 404 harmlessly; the page’s `typeof API_BASE` guard keeps working. |
| D6 | The `.spec` annotation asides ("Semantic palette", "What to look at") and the static demo badges do not ship; the notices strip renders live state instead. (The topbar this originally also covered has since gone entirely — D27.) | §6.2's accepted-exception note is explicit that `.spec` is the annotation layer, toggled off in mpo-ui and "never ships in the product". The static badges were prototype chrome; the wireframe (§7.2) shows the notices as live state. |
| D7 | The fixtures adapter carries environment failure knobs (`SCENARIO_FIXTURES_LATENCY_MS`, `_FAIL`, `_FAIL_SCHEMA`, `_FAIL_SLEEVES`, `_FAIL_EXPORT`). | §4.4 requires every §10 state — including error and timeout — to stay reachable through the fixtures adapter over the real stack. Deterministic knobs are the only way to reach them on demand without poisoning real combinations permanently. Documented in `dashboard.env.defaults`. |
| D8 | Scenario state is a file-backed store (one JSON per scenario, atomic writes, 24h retention), not in-memory. | The host launches pmgService with `--workers 2`; an in-memory store would 404 on whichever worker did not create the scenario. Files are worker-safe and survive restarts. Directory configurable via `SCENARIO_STORE_DIR` (default under the system temp dir). Resolved-portfolio payloads remain an in-process cache — recomputable, so per-worker is correct. |
| D9 | The sleeve library is authored data in `sleeves.py`: the prototype's library minus its Cash category, plus the single Asset Allocation Strategies sleeve (product: Tactical Tilt Fund). | The package supplies no separate sleeve source ("PMG sleeve library — stub: same [nothing, supplied]"), and the prototype's data is the only authored library in the hand-off. Cash is not in the supplied weight universe (§16 item 13); AAS carries exactly one auto-attached sleeve (§2.6). Production replaces this module behind the same function. |
| D10 | `advisors.xlsx` (24 advisors, name + office) is authored and shipped beside `advisors.py`. | The reference adapter is specified as Excel-backed (§4.2 item 7) but no workbook was supplied. The six advisors the prototype named are all present. |
| D11 | The analytics library's `core/dataModel/dataSources/vendor/IMF.py`: the WEO release download in `get_region_inflation_forecast` is wrapped in try/except. | The function (mid-migration on this branch) already discards the download's result in favour of the vendored `weo_2026_1.csv`, but still paid for — and intermittently failed on — the network call (`httpx.ReadTimeout` observed twice, killing `resolve_portfolio`). The guard preserves the in-progress structure and makes resolves deterministic offline. |
| D12 | The popover's controls mirror the base tier (Allocation select + the two exclusion tick boxes + Risk level), not the prototype's compound six-variant select. | The spec never enumerates the popover's controls (gap G2). The prototype's compound select predates Q32 ("four plus two tick boxes" beats a compound axis), cannot express ex-TAA comparisons (half the 84-combination space, §2.1 scopes excludeTAA per portfolio), and labels variants inconsistently with §2.3's derived names ("Full" in the picker produced a column headed "Full … ex RE"). Mirroring the base tier keeps every key-entry control identical. |
| D13 | The analytics portfolio is built zero-padded to all 19 codes (`include_zero_weights=True`); the screen payload still comes from held rows only. | Padding changes no number (verified equal to 1e-12) and gives every portfolio an identical asset set, which is what lets `Reporting.get_portfolios_table` union heterogeneous portfolios — its own union-with-zero-fill convention — instead of raising `InvalidIndexError` on duplicate spacer labels. | D14 | The export workbook drops the `assumptions` sheet `generate_report()` always writes. | Open item 6 records the export as "the three on-screen tables **and nothing else**". Removing the sheet honours that reading; restoring it is one deleted line. |
| D15 | Scenario retention is 24 hours (`SCENARIO_RETENTION_HOURS`), and the 404 message says so. | Open item 8 (retention) is undecided and blocks "only the wording of the message"; a number was needed to write the message. Configuration. |
| D16 | The analytics library's `core/estimator/assetReturnEstimator.py` optimised: the per-window normalisation statistic is memoised in a shared `_window_cache`; the discarded `convert_asset_to_currency` call is removed; the beta cache is keyed on `(name, currency, start, end, normalized, model hash)` rather than on `hedging_ratio`. | Profiling put 168s of a 255s cold portfolio in this one function, most of it re-orthogonalising the same factor windows once per asset. The change is performance-only and **bit-identical** — `tests/test_tier0_beta_equivalence.py` re-implements the original verbatim and asserts equality, and live output is unchanged to the digit. | D17 | A third ScenarioPort, `baked`, serves precomputed results from disk (`bake.py` + `bakedAdapter.py`), selected by `SCENARIO_ADAPTER=baked`. | The tool is a lookup over a closed space — 68 combinations per currency × 4 hedging policies (DECISIONS Q2) — so the analytics can be computed once per data version instead of per request. ## Adapter-side decisions (invited by the brief)

| Area | Decision |
|---|---|
| Caching | Three layers: the loader's own memoised context (per currency) and portfolio (per currency+weights+hedging), plus a finished-payload cache per (currency, hedging, key) in the live adapter. Warm resolves are sub-millisecond, which is what makes rehydrate-after-refresh read as instant under the 200ms rule. |
| Concurrency | One coarse `RLock` serialises analytics compute (its caches and the mutable, self-memoising `SAAPortfolio` are not demonstrably thread-safe; FastAPI runs sync handlers in a threadpool). Columns are separate HTTP requests, so per-column UI states are unaffected. |
| Lazy setup | `CAppConfig.setup()` (~12–14s) runs on first analytics use, not at service start — a fixtures-configured service never pays it and `/health` is immediate. |
| Sessions | See D8. Scenario ids are `sc_` + 12 hex chars; the id rides the URL via `history.replaceState` (no route — §7.1's one-route constraint holds; host pages already use query deep-links). |
| Error mapping | `ValidationError → 422 {error, field}` · unknown/expired scenario `→ 404 {error}` · `LookupError` from the loader `→ 422` (the availability set should have prevented the selection) · `AnalyticsError` and unexpected engine failures `→ 502 {error}` · auth `→ 401 {loginUrl}` / `403 {error}`. The Flask proxy supplies 502/504 when the service is down/slow. |
| Module layout | Everything transplantable in `pmgService/scenario/`; endpoints as a block in `dashboardRouter.py`; auth through `..core.accessControl` — the host's own seam. |
| Measured performance (the brief: "measure it and record the number") | Full record in `PERFORMANCE.md`. Headline: a cold portfolio was ~255s, is ~97s after the Tier 0 fixes (D16), and is **~1ms served from the bake** (D17). Warm repeats were already <1ms through the payload cache. `CAppConfig.setup()` ≈ 9–14s, once, and only on the live path. Export ≈ 50s warm through `Reporting`. The proxy's 300s timeout covers the worst single live resolve. |
| Analytics data coverage | This database carries currency configs for **USD and GBP only** at dataversion 1; CHF and EUR cannot resolve at all (see `PERFORMANCE.md`). The UI offers four currencies because the supplied weights carry four. Left as-is rather than silently narrowing the option list: which currencies PMG intends to serve is a product decision, and the bake manifest records exactly which are covered. |
| Real premia rows | The full 3×3 grid (VaR, CVaR, PoL × 1M/1Y/3Y), matching `get_var_pol_tbl`'s own layout; the prototype's 6-row subset was placeholder data. The rows are server-supplied, so the UI renders whatever arrives. |
