1Purpose & scope

This document is the complete build reference. Nothing in it is left for the implementer to invent; where a decision is still open it is listed in §16 and marked as such.

1.1Who this is for

The service belongs to the Portfolio Management Group (PMG) at Goldman Sachs. Its users are Private Wealth Advisors (PWAs), who use it to build portfolio implementation models and submit them to be invested in. Output reaches end clients, so the page is treated as client-facing throughout.

1.2The two steps

StepWhat the PWA doesOutput
1 — Asset allocation Enters the client mandate, sets the scenario basis, defines a base portfolio, and compares it against up to three alternatives. Allocation table, two summary charts, three-section risk dashboard.
2 — Implementation Attaches one PMG-authored sleeve of investible products to each category of the base portfolio. Product-level model with weights, fees and notional, exported to Excel.

Both steps live in one page. They share mandate, basis and portfolio state, and the host has no shared JavaScript store — two page folders could not have shared it. The steps are tabs inside a single document.

1.3What it is called

The product is the Epsilon Phi Proposal Tool, shortened to Proposal Tool in the interface. That name appears on the landing (§7.1), in the workspace topbar, in the page folder and route (proposalTool/), and on this document.

A “scenario” is what a PWA builds; the Proposal Tool is what builds it. The domain noun is unchanged and stays everywhere it already is — scenarioId, the /api/scenario/… surface, ScenarioPort, the Scenario basis rail tier, the New scenario dialog and the export filename. Renaming the product does not rename the thing it produces, and conflating the two would churn the whole HTTP contract for a cosmetic change.

1.4Out of scope

  • Simulation. No wealth simulation, no path generation. The export must pass include_wealth_simulations=False.
  • Optimisation. Weights are looked up, not solved.
  • Submission. Not in this UI. The terminal action downloads the tables to Excel.
  • PMG accounts. There is no account concept on this page; the mandate is entered directly.
  • ISG schema scoping. The data is not schema-scoped. No isgCodeSelector.js, no schemaCode parameter.
  • Roles. One role. §10.4 specifies the extension point.
  • Link sharing. Deferred.

2.5The $20m private-assets rule

Private assets are blocked for mandates under $20,000,000. Private assets means Private Equity and Other Private Assets. Hedge funds are not private assets. This gates which allocations exist in step 1; at implementation there is no further gating.

AllocationPrivate assets heldUnder $20m

A sub-$20m mandate has two allocations available out of six. The availability set is therefore a function of (currency, hedging, mandateSize), not of currency and hedging alone.

2.6Sleeves
SourceA library authored by PMG
AssemblyNo one can assemble sleeves. PWAs select only
ChoiceAround five per category
Identity(category, name). The name carries the entire differentiation — it describes the implementation vehicle, e.g. GSAM Separately Managed Account, Funds Only, ETF & Mutual Funds for IGFI; Active-Passive, Passive, Concentrated Active for Public Equity
MutabilityA sleeve is a fixed block. Weights cannot be edited, products cannot be added or dropped
CompletenessEvery category must carry a sleeve before the model can be exported

A sleeve's product weights sum to 1. The category's weight in the asset allocation is distributed proportionally across them.

The implementation screen is a picker with a completeness gate, not an editable grid. This is the single largest simplification in the module. Because the name carries all the differentiation, a plain select per category is the honest control — a card list would invent hierarchy that does not exist.

2.7Comparison rules

  • Four portfolios maximum — one base plus three comparisons.
  • The base is pinned to the first column, cannot be removed, only changed, and is the only portfolio that gets implemented.
  • No deltas. No difference column, no change highlighting.
  • A combination already on screen cannot be added again.
  • Column order is insertion order, never completion order (§15.3).

Why availability is fetched up front

The combination space is only 84 wide. Fetching which combinations exist when the scenario opens lets the UI render the rest as unselectable, which means “no portfolio matches your parameters” never occurs as an error. One request removes an entire failure mode. Do not implement a no-match error path; implement the availability set.

4The port

Everything project-specific sits behind one Protocol. This is the contract the host must satisfy.

# the adapter the host implements
from typing import Protocol, Sequence

class ScenarioPort(Protocol):
    """Everything the UI needs from the host. Eight methods, no more."""

    def get_schema(self, basis: BasisInput, mandate: MandateInput) -> Schema:
        """Field definitions, option values, validation rules, and the set of
        (allocation, excludeRE, excludeTAA, riskLevel) combinations that have a
        stored portfolio for this currency, hedging policy AND mandate size.

        Mandate size matters: private assets are blocked under $20m, which
        removes four of the six allocation variants. Must be cheap - called on
        scenario open and whenever the basis or the mandate changes."""

    def search_advisors(self, query: str, limit: int = 20) -> Sequence[Advisor]:
        """Typeahead over the Primary PWA directory. The reference adapter reads
        an Excel file; production reads a database table."""

    def validate_mandate(self, mandate: MandateInput) -> None:
        """Raise ValidationError with a field name and message if invalid. The UI
        enforces the same rules client-side for immediacy; the server is
        authoritative."""

    def resolve_portfolio(
        self, basis: BasisInput, key: PortfolioKey
    ) -> PortfolioResult:
        """Look up the stored allocation, construct the portfolio, compute the
        analytics, return everything the tables need. THE EXPENSIVE CALL - may
        take seconds. Implementations should cache."""

    def list_sleeves(self, category: str, basis: BasisInput) -> Sequence[Sleeve]:
        """The PMG-authored sleeve library for one category. A sleeve is a fixed
        block: name plus products whose weights sum to 1."""

    def build_export(
        self, basis: BasisInput, mandate: MandateInput,
        portfolios: Sequence[PortfolioResult],
        implementation: Implementation | None,
    ) -> bytes:
        """Return an .xlsx byte stream. The reference adapter calls
        Reporting.generate_report(include_wealth_simulations=False)."""

    def capabilities(self) -> dict:
        """{"canExport": bool, "canEdit": bool}. One role today; this is the seam."""

    def describe(self) -> dict:
        """Data version, source, as-of date. Surfaced in the footer for support
        and reproducibility."""

From a UI selection to analytics

The loader now carries the whole chain. get_context(currency) builds the epsilonPhi analytics context, and get_portfolio(currency, weights, hedging_option) returns an SAAPortfolio built against it. That portfolio object is the source of every number the tool displays — the metrics band, the charts and all three sections of the risk dashboard read off it.

Both are memoised, because both are expensive: the context is cached per currency, of which there are four, and the portfolio is cached on (currency, weights, hedging_option). get_context is named for what it returns and is not ScenarioPort.get_schema() — that one returns the UI's fields, options and availability set, and the two have nothing in common but a former name.

5Front-end architecture

Plain browser JavaScript. No framework, no bundler, no module system — because the host has none.

There is no import. The host loads scripts with <script src> and order is load-bearing. This page ships one JavaScript file whose internal order is the dependency graph.

5.2The host prelude

'use strict';

// The Flask frontend proxies /api/* to FastAPI, rewriting /api/<x> to
// /api/v1/<x>. On a host page globals.js has already set API_BASE; this
// guard keeps the page working when opened standalone.
if (typeof API_BASE === 'undefined') {
    window.API_BASE = window.location.origin + '/api';
}

async function apiFetch(path, opts) {
    // read off window rather than the bare global: identical in a browser,
    // and it does not depend on window === globalThis
    var resp = await fetch(window.API_BASE + path,
                           Object.assign({credentials: 'same-origin'}, opts || {}));
    if (!resp.ok) {
        var msg = 'Request failed (' + resp.status + ')';
        try {
            var body = await resp.json();
            if (body && body.loginUrl) { window.location = body.loginUrl; return; }
            if (body && body.error) msg = body.error;
        } catch (e) { /* non-JSON error body */ }
        throw new Error(msg);
    }
    return resp.json();
}

credentials: 'same-origin' matters: the page is served from inside the host app, so the kerberos cookie travels automatically. The UI never handles a token.

5.3State shape

{
  phase:   "landing" | "workspace",  // precedes any mandate; see §7.1
  scenarioId: "sc_7fa2…",
  mandate: { topAccountSize, mandateSize, primaryPwa, editing, error },
  basis:   { currency: "USD", hedging: "Hedged" },
  schema:  { allocations[], riskLevels[], categories[], availability: Set, rules },
  step:    "aa" | "impl",
  columns: [                       // index 0 is always the base
    { key: {allocation, excludeRE, excludeTAA, riskLevel},
      status: "loading" | "ready" | "error",
      requestedAt: 1724920000000,  // drives the 200ms skeleton threshold
      error: null,
      data: { name, weights, categories, has, metrics, stress[], premia[] } }
  ],
  sleeves: { "<category>": "<sleeve name>" | null },
  export:  { status: "idle" | "working" | "error" }
}

Every column carries its own status. There is no global loading flag. Three columns can be resolving while a fourth shows an error and the base is ready — and the tables must render all four states at once without special-casing.

5.4Rendering

Direct DOM writes, matching the host. Two rules keep it correct without a virtual DOM:

  • Delegate events at the document, never bind to elements that re-render.
  • Preserve focus across re-render. Record document.activeElement.id and the selection range before replacing markup; restore after. Without this, the typeahead loses the caret every time a column resolves.

5.5Adding a second page later

If the product ever needs one, follow the host's convention rather than introducing a router: a new folder, a new Flask route, a new nav link. Shared logic moves to dashboard/static/js/ and is included by both pages in the correct order. Do not add a client-side router — it would be the only one in the host and would fight the back button.

8.3Fee model

The management fee is the GS advisory fee, layered on top of the product cost — additive, not nested.

all-in per product  = product cost + management fee
weighted fee        = (product cost + management fee) × weight
portfolio total fee = Σ weighted fee

Product cost and management fee display as 2dp percent. The weighted fee displays in basis points to one decimal, and this is a deliberate departure: at 2dp a thinly-weighted product renders a real fee as 0.00% — 0.33% all-in on a 1.40% weight is 0.0046%. A fee of zero on a client-facing document generates a phone call.

8.4The rounding rule

Every printed figure derives from the printed weight. A client-facing table must reconcile against what it shows, not against what it computed. Rounding the output is not the same as rounding the input — only the second survives someone with a calculator.

  1. Round each weight to 2dp by largest remainder, so the column sums to exactly 100.00% rather than 99.99% or 100.01%.
  2. Derive notional from that rounded weight against the mandate size, then round to the nearest $100.
  3. Derive the weighted fee from that rounded weight too.

For a mandate that is a round million, step 2's rounding is a no-op: mandate / 10000 is already a multiple of 100, so notional lands on a hundred by construction.

InvariantHolds
Every line is a multiple of $100yes
Lines sum to the mandate exactlyyes
Category subtotals sum to the mandateyes
Weights sum to exactly 100.00%yes
Printed weight × mandate = printed notionalzero drift
Printed (cost + mgmt) × printed weight = printed weighted feezero mismatches

Notional is taken against the mandate size, not the top account size.

11.2Saving the mandate

  1. Client-side validation on blur; server is authoritative on submit.
  2. POST /api/scenario. If validate_mandate() raises, the dialog stays open and the message attaches to the named field.
  3. Refetch the schema — mandate size gates the $20m rule, so the available allocations may have changed.
  4. If an existing column is now invalid it is dropped, and the user is told which.

11.3Building and adding portfolios

  1. Column inserted in loading state with its derived name — the name needs no server call.
  2. POST /api/scenario/{id}/portfolio fires; a 200ms timer starts.
  3. Whichever lands first wins: response before timer means no skeleton ever appears.
  4. On success the column becomes ready; tables and charts re-render.
  5. On failure it becomes error with Retry. Others unaffected.
  6. Concurrent adds may return out of order. Columns hold their array position, keyed by {allocation, excludeRE, excludeTAA, riskLevel}; a late response is matched to its column, and one for a removed column is discarded silently.

11.4Rebuild on basis change

Changing currency or hedging must not fire on the select's change event. At up to 5s per portfolio, a four-column rebuild is a twenty-second operation. It requires explicit confirmation.

  1. The select updates optimistically; no request fires.
  2. An inline confirmation appears in the tier: “Rebuild 4 portfolios in CHF?” with Rebuild and Cancel. Cancel restores the previous value.
  3. On Rebuild: fetch the new schema first. Any combination unavailable under the new basis is dropped and named — “Ex Alts Low Vol is not available in CHF and has been removed.”
  4. Surviving columns enter loading together and re-resolve, keeping their allocation, exclusions and risk level. Order is preserved; the base stays the base.
  5. Any attached sleeves are invalidated (§11.6).

11.5Changing the base

  1. Column 0 is replaced and re-resolves.
  2. If a comparison now duplicates the new base it is removed and announced — silent disappearance of a column the user built is unacceptable.
  3. Comparisons are otherwise untouched; they are independent combinations.
  4. Changing the Allocation select recomputes the Exclude RE tick box: if the new allocation cannot hold real estate, the box becomes checked and disabled.
  5. If the current risk level is unavailable for the new allocation, fall to the first that is.

11.6Invalidating the implementation

Sleeves attach to the base portfolio's categories. Anything that changes those categories or their weights invalidates the attached sleeves.

Whenever a sleeve is dropped the completeness gate re-closes and the export disables again.

11.7Attaching a sleeve

  1. The rail lists only the categories the base's variant has, each with its allocation weight.
  2. Selecting a sleeve inserts its product rows immediately — the library is cached, so this is not a round trip.
  3. Weights, fees and notionals recompute across the whole table, because the largest-remainder rounding is global (§8.4).
  4. When the last category is filled the export enables and the badge flips to .b-ok.

11.8Removal and refresh

  • Remove works on any comparison in any state, including one still loading — abort the in-flight request rather than waiting.
  • The base cannot be removed. Its row shows the Base chip where the remove control would be, not a disabled control.
  • On load with a scenario id, GET /api/scenario/{id} restores mandate, basis, columns and sleeves. Columns come back loading and re-resolve.

15Implementation traps

Each of these was hit while building the prototype. Every one is a silent failure — the code works and the output is wrong.

15.1The background shorthand destroys the select caret

The dropdown arrow is a background image. Any later rule setting the background shorthand on a select resets background-repeat to repeat and background-position to 0% 0% — and the 11 × 7px chevron tiles across the whole control.

/* WRONG — the caret tiles */
.rail select { background: var(--rail-input-bg); }

/* RIGHT */
.rail select { background-color: var(--rail-input-bg); }

Defensively, set background-size: 11px 7px on the base rule. The control still works when this breaks, so it survives functional testing and is found by a user.

15.1aThe cached portfolio is shared — do not mutate it

get_portfolio() is memoised, because building an SAAPortfolio is expensive. It therefore hands the same instance to every caller with the same (currency, weights, hedging). SAAPortfolio is mutable and memoises its own analytics — _sigma, _risk_betas, _risk_premias — so mutating it changes the numbers every other holder sees. With four columns on screen, that is one column silently reporting another's risk.

This is why hedging is a constructor argument and part of the cache key, rather than a set_hedging_option() call the caller makes afterwards. Ask for the hedging you want:

portfolio = get_portfolio(currency, weights, hedging_option=basis.hedging)

If you genuinely need to change a portfolio, take a copy first with deepcopy(). Treat what comes back from the cache as read-only.

15.2Column arithmetic

The risk dashboard's mixed colspan (§9.2) and the implementation table's thirteen columns (§9.3) are both easy to get right at one portfolio count and wrong at another. Write the assertions.

15.3Concurrent adds return out of order

Three columns added in quick succession are three concurrent requests; the third may resolve first. Columns must hold their array position, keyed by their combination, and a late response must be matched to its column rather than appended. A response for a column the user has already removed is discarded silently.

15.4Zero, dash and blank are three different things

0.0% is a holding rounded to nothing. — is a sleeve the portfolio does not contain. Blank is a category the allocation variant does not have. Collapsing any two of these loses information the comparison depends on.

15.5Sticky columns need an opaque background per row state

A sticky column with a transparent background lets data scroll underneath it. Every sticky cell needs an explicit background from the same token as its row — including category, total, metric and alternating rows, which each have their own fill. With two pinned columns in the implementation table, this doubles.

15.6Focus loss on re-render

Columns resolve asynchronously and re-render the tables. If the user is typing in the rail when a response lands, a naive innerHTML replacement destroys focus and caret position. §5.4 specifies the save-and-restore; it is not optional.

15.7The skeleton flash

Showing a skeleton immediately makes a 40ms cached response flash. Never showing it makes a 5s response look broken. The 200ms threshold is the resolution — implement it as a timer cancelled by the response, not as a minimum display duration.

15.8Renaming weight keys breaks metrics silently

When the category model changed from five invented categories to the seven real ones, the weight keys changed with it. Three formulas — return, volatility and the crisis calculation — still referenced the old keys, so they produced NaN.

Every test passed throughout. They checked structure and reconciliation — column counts, weights summing to 100%, notionals totalling the mandate — and never that the numbers were finite. One assertion even passed spuriously, because NaN !== NaN is true. Ship a finiteness guard over the whole combination space plus a check that no rendered surface contains NaN or undefined. Reconciliation tests pass happily on nonsense.

15.9Rounding the output is not rounding the input

Rounding the notional to the nearest $100 makes the figures look deliberate but does not make them reconcile: the drift comes from the weight's 2dp rounding. Printed 7.02% × $26m is $1,825,200 while the true weight is 7.0150%. Only deriving every figure from the printed weight (§8.4) closes it.

15.10'use strict' and the global object

The host's convention is to reference the bare global API_BASE, which works only because window === globalThis in a browser. Read window.API_BASE instead: identical at runtime, and testable outside one.
