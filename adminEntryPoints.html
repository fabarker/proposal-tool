What is there now, and why it is weak

Today

Two uppercase text links under the brand

They sit inside .rail-brand, immediately beneath Proposal Tool, above the mandate. Three problems:

  • They vanish when the rail collapses. The collapse rule fades every child of the brand block — body.rail-collapsed .rail-brand>a{opacity:0} — so at 48px both tools are unreachable. That is the real defect here, not the styling.
  • They compete with the identity. Two shouty uppercase lines directly under the product name read as part of the masthead rather than as tools.
  • They sit at the top of a workflow rail whose job is the mandate, the basis and the sleeves. A tool used occasionally is in the busiest position on the page.

Six placements

Option 1 recommended

A utility bar pinned to the foot of the rail

A thin strip below the last tier, separated by a rule and slightly darker than the rail. Two icon buttons, labelled on hover and by aria-label. The rail is already display:flex;flex-direction:column, so this is one flex child with margin-top:auto.

ForOut of the workflow's way but always in the same place. Survives the collapse — the icons stay at 48px, only the caption drops. Room for a third tool later without touching the masthead.

AgainstBottom-left is a low-attention corner; a first-time admin may need telling once.

Option 4

One admin icon that opens a menu

A single button — a shield, or a cog — opening a small popover listing both destinations with a line of description each.

ForOne affordance instead of two, and it scales: a fifth admin tool is a row in a menu rather than another icon competing for space. The descriptions make it self-explaining, which two bare icons never are.

Recommendation

Option 1 for the home, Option 2 for the shortcut, Option 6 for the landing page. They answer different questions and do not overlap:

QuestionAnswered by
“Where do these tools live?”The rail's utility bar — one fixed place, visible in both rail states, on every page past the landing.
“This sleeve is wrong, fix it now”The icon on the Sleeves heading, opening the repository at the category and type already on screen.
“I came here to maintain the library, not write a proposal”The landing tiles.

That is three entry points for two tools, which sounds like a lot until you notice the current build already has four, all of them text and two of them invisible half the time.

Whatever is chosen, one thing has to be fixed. The collapse rule fades everything in the brand block. Any icon placed there inherits that, so either the icons move out of the block (Options 1, 5) or the rule has to stop applying to them (Options 3, 4). Option 1 is the only one where the collapsed rail is better than the expanded one — a 48px strip of icons is exactly what that state is for.

The icons

Inline SVG on a 20px box, 1.6 stroke, currentColor so one file serves the navy rail and the white landing page. No icon font and no sprite fetch — the page has neither today and neither is worth adding for four glyphs.

Sleeve repositoryStacked layers — a sleeve is a block of products, and the library is a stack of them.
Product catalogueA table with a header row — which is literally what the view is.
AdministrationA shield, for Option 4's single button. Says restricted without saying settings.
AlternativeA cog. Conventional, but reads as preferences, which these are not.

Each button needs an aria-label and a visible tooltip on hover and focus — an icon alone is not a label, and the two are only distinguishable once you know them. In the utility bar the word Admin beside them does that job in the expanded state.

What it would take

  • Option 1 — a .rail-admin-bar flex child with margin-top:auto, the two buttons, and a collapsed-state rule that hides the caption but not the icons. The existing renderEntryLinks already toggles on canAdmin; it would toggle this instead. S
  • Option 2 — one button in the sleeve tier's .tier-h, passing the current category and type into openRepository so it lands there. Needs the console to accept an opening selection, which it does not yet. S
  • Option 6 — replace the two .lp-admin anchors with the tile markup. XS
  • Icons as a small inline <svg><defs> block in the page shell, referenced with <use>. XS
