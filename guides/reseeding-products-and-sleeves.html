Re-seeding Products and Sleeves

How to replace the product catalogue and reload the sleeve library on the Cyrus project, including editions, their rules and the implementation types, without losing the record of what was there before.

For whoever looks after the tool's data on Cyrus Project H:\cyrus-repo\isg-cyrus-pmg Written 15 October 2026

What lives where

The products and the sleeves are kept in different ways, so they are re-seeded in different ways. Products are a file the tool reads. Sleeves are rows in a database the tool writes to, which keeps a full history of every change.

DataKept inSet byHow you change it
Product catalogueA CSV or Excel file SCENARIO_PRODUCTS_SOURCESwap the file. Read again as soon as it changes, with no restart.
Sleeve librarysrc\var\sleeves.db SCENARIO_SLEEVES_DBImport a file with the sleeve tool, or edit sleeve by sleeve in the console.
Funding split, overlay rulesThe same sleeves.db— The console only. A sleeve import does not touch them.
Fee cardfeeRates.csv in the packageSCENARIO_FEES_SOURCE Not covered here; see the note on fees.
Proposals and account requestssrc\var\proposals.db SCENARIO_REGISTER_DBNever re-seeded. Nothing below touches it.

The order matters, because each layer checks the one before it: fee card → products → sleeves. A product must name a fee group the fee card knows, and a sleeve may only hold products the catalogue knows.

Keep the working files outside the project

Use a folder of its own, such as H:\pt-seed, for exports, new files and backups, the same way the updates live in H:\pt-update. Nothing you prepare then ends up in the project's own folders.

One-time setup: a run configuration for the sleeve tool

Everything below is done by one small program, the sleeve tool (cyrus_pmg.pmgService.scenario.sleeveTools). It must see the same settings as the service: the same product file, the same database and the same portfolio extract. The simplest way to guarantee that is to copy the service's own run configuration in PyCharm.

Copy the service's configuration

In PyCharm open Run → Edit Configurations…, select isgPMGService and press Copy Configuration (the icon of two pages, or Ctrl+D). Name the copy Sleeve tools.

Point it at the sleeve tool

Beside the script field there is a drop-down that reads Script path; change it to Module name and type cyrus_pmg.pmgService.scenario.sleeveTools. In Parameters type --census. Leave the working directory and the environment variables exactly as they were copied. Press OK.

Run it once to see what you have

Choose Sleeve tools in the run drop-down at the top right and press the green triangle. The census prints in the Run window. It is read-only, and it is safe to run at any time, with the service running or not.

The census is the first thing to read and the last thing to check. Its top lines tell you where everything is:

store      H:\cyrus-repo\isg-cyrus-pmg\src\var\sleeves.db
           108 sleeves, seeded 2026-10-15T22:49:31 from …\sleeves.csv
           schema v6 · 312 revisions on record · 102 sleeve(s) archived
           4 labelled edition(s) with rules
catalogue  H:\…\products.csv
           73 products, modified 2026-09-27T16:53:51
types
  PMG Multi-Asset Portfolio     27 sleeves
  PMG ESG                       32 sleeves
  US Onshore                    26 sleeves
  Irish Onshore                 23 sleeves
fixed      Asset Allocation Strategies, Hybrid Fixed Income
  • store is the sleeve database the tool is using. Back up this file.
  • catalogue is the product file the tool is reading. Replace this file to re-seed products.
  • sleeves counts every edition, a sleeve's fallback included. labelled edition(s) with rules counts only the editions that carry rules.
  • Anything wrong is listed underneath, under BROKEN or NOT IN THE CATALOGUE. The run then ends with exit code 1 instead of 0.

To run anything else, edit the configuration's Parameters, for example to --export H:\pt-seed\library.csv, run it, and set it back to --census afterwards. Each run does one thing.

Re-seeding the product catalogue

There is no import for products: the catalogue is the file. Replacing the file is the whole re-seed. The tool reads it again the next time it is asked for a product, and refuses the whole file if any row is wrong, so a bad file never half-loads.

The columns

Row one holds the headers; the tool finds columns by their names, so the order is free. A row whose first cell is empty is skipped.

ColumnRequiredWhat goes in it
ProductIdYesThe product's permanent id, such as gs-access-em-equity-etf. Sleeves refer to products by this id, so never change one that is in use. Must be unique.
NameYesWhat the PWA sees. Cannot be empty.
TickerColumn yes, value noMay be blank, e.g. for an SMA.
AssetClassYese.g. Emerging Markets, IG Corporate.
StyleYesActive or Passive.
VehicleYese.g. ETF, Mutual Fund, SMA, UCITS.
SourceYese.g. Internal.
LiquidityYese.g. Daily.
ExposureCurrencyYese.g. USD.
ProductCostYesA percentage written as a number: 0.25 means 0.25%. Not negative.
FeeGroupYesOne of the fee card's groups: Passive, Core Active, Specialist Active, Alternatives, Asset Allocation. The management fee comes from the fee card through this group, not from the product.
ShareClassOptionalDis or Acc, or blank.
DistributionYieldOptionalA percentage as a number, e.g. 3.20.
MinimumInvestmentOptionalIn currency units, e.g. 5000000.

Steps

Start from the current file

Run the census and note the catalogue path. Copy that file to H:\pt-seed twice: once as the backup (e.g. products-2026-10-15.csv) and once as the file you will edit (products-new.csv).

Make your changes in Excel

To add a product, add a row. To change one, edit its cells but keep its ProductId. To remove one, delete its row, but first read the next step, because sleeves that hold it will stop being offered.

Save with File → Save As → CSV UTF-8 (Comma delimited). An .xlsx also works, provided the catalogue is on the first sheet.

Check it before it goes live

In the Sleeve tools configuration, add one environment variable, SCENARIO_PRODUCTS_SOURCE = H:\pt-seed\products-new.csv, and run the census. The live service is not affected; only this run reads the new file.

A clean census ends with no BROKEN list. If a product your sleeves use is missing, the census names it and every sleeve that holds it:

BROKEN (6):
  Irish Onshore / Public Equity / Passive
      Product 'gs-access-world-equity-ucits' is no longer in the catalogue.
  …
NOT IN THE CATALOGUE (1):
  gs-access-world-equity-ucits  referenced by Irish Onshore / Public Equity / Passive, …

Either put the product back, or plan to change those sleeves in the same sitting (see the sleeves). If the file itself is wrong, a missing column, a duplicate id, an unknown fee group or a bad number, the census says so and nothing is read.

Remove the environment variable again when you are done.

Swap it in

Copy products-new.csv over the file at the catalogue path, under that file's own name. The service picks it up on its next request; press Ctrl+F5 on any open page. Run the census once more: the catalogue line should show today's time and the new count.

Undoing it

Copy the backup back over the catalogue file. Nothing else needs to change.

Re-seeding the sleeve library

A sleeve file is loaded with the sleeve tool's --import. The import checks every row the same way the console checks a save, and loads nothing if any row fails, so the library is never left half-changed. Every change it makes is recorded in each sleeve's history, and nothing is destroyed.

The vocabulary

WordMeaning
VariantThe implementation type the sleeve belongs to: PMG Multi-Asset Portfolio, PMG ESG, US Onshore or Irish Onshore. The PWA chooses this in step 2.
CategoryOne of the seven: Investment Grade Fixed Income, Hybrid Fixed Income, Other Fixed Income, Public Equity, Hedge Funds, Private Equity & Other Private Assets, Asset Allocation Strategies.
SleeveThe name the PWA picks, e.g. Global Equity Core.
EditionA version of the same sleeve for particular portfolios. Left blank it is the fallback, the version everyone gets unless a labelled edition claims their portfolio. Filled in, e.g. GBP, it is a labelled edition and needs at least one rule.
RuleWhich strategic portfolios a labelled edition is for, by currency, risk level and allocation type.

The two files

The sleeves file has one row per product in an edition:

Variant,Category,Sleeve,Edition,ProductId,Weight

Weight is a fraction, so 60% is 0.6. In Excel you may format the column as a percentage and type 60%, which is the same value. Each edition's weights must total exactly 100%, and a product may appear only once in an edition.

The rules file has one row per rule, and sits beside the sleeves file with .rules added to its name (library.csv → library.rules.csv):

Variant,Category,Sleeve,Edition,Currency,RiskLevel,AllocationType

A library with no labelled editions needs no rules file. An Excel workbook can carry both instead: a sheet named Sleeves and a sheet named Rules.

Add to the library, or replace it

ParametersWhat happensUse it when
--import FILEAdds and updates. An edition in the file with the same variant, category, sleeve and edition label as a live one replaces it as a new revision, keeping its identity and history. Everything not in the file stays as it is.You are changing or adding some sleeves.
--import FILE --replaceReplaces. Every live sleeve is archived first, each with a final revision recording who and when, and then the file is loaded as the whole library, all in one step.You want the library to be exactly the file.
A replace loads exactly what the file holds, even if that is nothing

An empty or half-finished file with --replace archives the whole library and loads what little is there. The import cannot know you meant more. Run the census straight after; if anything is missing, see undoing a re-seed.

Steps

Export what is there now

Set the Sleeve tools parameters to --export H:\pt-seed\library.csv and run. It writes library.csv, and library.rules.csv beside it if any edition has rules. This is the starting point for your edits, in exactly the right format.

Keep a backup

Copy the export to H:\pt-seed\library-2026-10-15.csv (and its rules file the same way). Then stop isgPMGService and copy the store file (src\var\sleeves.db) to H:\pt-seed\sleeves-2026-10-15.db. Copy the database only while the service is stopped.

Edit in Excel

Open library.csv, change, add or delete rows, and save it as CSV UTF-8. If you add labelled editions, add their rules to library.rules.csv. Create that file with the header line above if the export did not write one. The next section shows how to write editions and rules.

Import

Set the parameters to --import H:\pt-seed\library.csv --replace (or without --replace to add and update only) and run. Success reads:

replaced the library with 108 editions from H:\pt-seed\library.csv (with 5 rule(s))

A refusal names the problem, and nothing has changed:

REFUSED (weights): Weights sum to 90.00%; a sleeve must sum to exactly 100%.
nothing was written

Fix the file and run again. The table of refusals lists the usual ones.

Check, then start the service

Set the parameters back to --census and run. Look for no BROKEN list, the counts per type you expect, and an exit code of 0. Then start isgPMGService, dashboardFrontend and optimizationService, and press Ctrl+F5 on the page.

Editions, rules and types: how to seed each kind

All the examples below were loaded through the import and checked with the census before this guide was written. Each one is a set of rows to add to library.csv and, where it has rules, library.rules.csv.

How a rule reads

  • Within a row, every filled cell must match (AND). A blank cell means any value.
  • Several values in one cell are separated by |, and any of them matches (OR): LowVol|Conservative.
  • Several rows for one edition mean the edition applies if any row matches (OR).
  • A rule must fill at least one cell. A rule that matches everything is what the fallback is for.
CellValues it accepts
CurrencyUSD GBP CHF EUR
RiskLevelLowVol Conservative ConsMod Moderate ModAgg Agg Higher Risk All Equity
AllocationTypeFull Core ex-Alts ex-HFs NA (NA is the all-equity portfolio, which has no allocation type)

The values are written exactly as above, capitals included. Only values present in the current portfolio extract are accepted.

Which edition a portfolio gets

  1. If exactly one labelled edition's rules match the portfolio, that edition is served.
  2. If none match, the fallback is served.
  3. If none match and there is no fallback, the sleeve is not offered for that portfolio at all.
  4. Two labelled editions of one sleeve may never claim the same portfolio. The import refuses it, naming the portfolios they share.

The PWA never sees which edition applied: they pick the sleeve by name, and the tool serves the right products.

1. A plain sleeve: one fallback, no rules

PMG Multi-Asset Portfolio,Public Equity,Global Equity Core,,gs-us-equity-insights-fund,0.6
PMG Multi-Asset Portfolio,Public Equity,Global Equity Core,,northbrook-intl-equity,0.3
PMG Multi-Asset Portfolio,Public Equity,Global Equity Core,,gs-emerging-markets-equity,0.1

The Edition cell is empty, so these rows are the fallback. No rules file entry is needed.

2. A different line-up for one currency

GBP portfolios get two different products; everyone else keeps the fallback above.

PMG Multi-Asset Portfolio,Public Equity,Global Equity Core,GBP,gs-access-world-equity-ucits,0.7
PMG Multi-Asset Portfolio,Public Equity,Global Equity Core,GBP,gs-access-em-equity-etf,0.3

and in the rules file:

PMG Multi-Asset Portfolio,Public Equity,Global Equity Core,GBP,GBP,,

3. Several risk levels in one currency

The cautious EUR portfolios, and no others, get a single passive product.

PMG Multi-Asset Portfolio,Public Equity,Global Equity Core,Cautious EUR,gs-access-intl-equity-etf,1
PMG Multi-Asset Portfolio,Public Equity,Global Equity Core,Cautious EUR,EUR,LowVol|Conservative|ConsMod,

4. Two unrelated groups: two rule rows

One edition for growth-minded USD portfolios and for CHF Full portfolios. These can't be said in one row, so the edition gets two.

PMG Multi-Asset Portfolio,Public Equity,Global Equity Core,USD growth / CHF Full,gs-us-equity-insights-fund,0.5
PMG Multi-Asset Portfolio,Public Equity,Global Equity Core,USD growth / CHF Full,gs-emerging-markets-equity,0.5
PMG Multi-Asset Portfolio,Public Equity,Global Equity Core,USD growth / CHF Full,USD,Agg|Higher Risk|All Equity,
PMG Multi-Asset Portfolio,Public Equity,Global Equity Core,USD growth / CHF Full,CHF,,Full

Examples 1 to 4 together make one sleeve, Global Equity Core, with a fallback and three labelled editions that never claim the same portfolio.

5. A sleeve offered only to some portfolios

Leave out the fallback and give the sleeve only a labelled edition. It then appears only where that edition's rules match; here, GBP portfolios.

PMG Multi-Asset Portfolio,Public Equity,UK Equity Income,GBP only,gs-access-world-equity-ucits,1
PMG Multi-Asset Portfolio,Public Equity,UK Equity Income,GBP only,GBP,,

6. The same sleeve under another implementation type

A sleeve belongs to one variant per set of rows. To offer Global Equity Core to ESG proposals too, repeat it under PMG ESG, with that type's own products. Its editions and rules are separate from the Multi-Asset ones.

PMG ESG,Public Equity,Global Equity Core,,gs-access-esg-us-equity-etf,0.5
PMG ESG,Public Equity,Global Equity Core,,gs-esg-international-equity,0.5
The four types are fixed in the tool

A file can use only PMG Multi-Asset Portfolio, PMG ESG, US Onshore and Irish Onshore. A new implementation type is a change to the tool itself, not to the data.

7. The two fixed categories

Hybrid Fixed Income and Asset Allocation Strategies hold exactly one sleeve per type, which the overlays attach automatically. Give each type one sleeve in each, with no labelled editions. A replace that leaves them out is accepted by the import, but the census then reports each missing one and ends with exit code 1, and the overlays have nothing to attach. Always keep them in the file.

Naming

  • Names and labels are tidied when loaded: spaces at the ends are removed, and doubled spaces become one.
  • Names that differ only in capitals or spacing count as the same name.
  • Label editions for the person reading the list, e.g. GBP or Cautious EUR. The word fallback is reserved.

Message beginsWhat it meansFix

Watch for a stray rules file

If the import finds no library.rules.csv beside your file, it looks for a sleeveRules.csv in the same folder and uses that. Keep H:\pt-seed free of old rules files, or name yours to match.

Undoing a re-seed

  • Quickest: import the export you took first, with --replace: --import H:\pt-seed\library-2026-10-15.csv --replace. The library is back as it was, and the detour stays on the record.
  • One sleeve: in the console, open the sleeve's history and restore it, or restore it from the Archive.
  • Everything, exactly: stop the service and copy sleeves-2026-10-15.db back over src\var\sleeves.db. This also brings back the funding split and overlay rules as they were at the backup.

What not to do

Don't delete sleeves.db to start again

A new, empty database seeds itself once from a seed file, and the tool's own instructions mention it. On a working system it costs far more than it saves:

  • every sleeve's history and the archive go;
  • the funding split and the overlay rules return to their starting values;
  • sleeves get new numbers, so the proposals already on record no longer point at the sleeves they were built from;
  • if the seed file is missing, the new database starts empty and stays empty: it never tries to seed again.

An import with --replace gives the same clean library without any of that.

A note on the fee card

If new products need a fee group the card does not have, the fee card must change first. Its tool, feeTools --accept, rewrites a file inside the package as well as the rate file. On Cyrus that makes the next tool update refuse to run, because it would overwrite a file changed by hand. Send a fee card change to be made with the tool's code instead.

Quick reference

Sleeve tools parameters

--census
What is there, and what is broken. Read-only.
--export FILE
Write the live library to FILE and FILE's .rules sibling.
--import FILE
Add and update from FILE; everything else stays.
--import FILE --replace
Archive the library and load FILE as the whole of it.
--archived
List archived sleeves.
--history ID
Every revision of one sleeve (the number in square brackets in a listing).
--activity
The 40 latest changes across the library.
