Re-seeding Products and Sleeves

How to replace the product catalogue and reload the sleeve library on the Cyrus project, including editions, their rules and the implementation types, without losing the record of what was there before.

For whoever looks after the tool's data on Cyrus Project H:\cyrus-repo\isg-cyrus-pmg Updated 16 October 2026, for the catalogue and fee card kept in the tool

What lives where

The products, the fee card and the sleeves are all kept in the database the tool writes to, which keeps a full history of every change. The product file and the fee card file are read once, the first time the tool opens after the update, to fill it; after that a new file goes in by importing it, and changing a file on disk changes nothing.

DataKept inSet byHow you change it
Product cataloguesrc\var\sleeves.db SCENARIO_PRODUCTS_SOURCEImport a product file on the Repository's Catalogue, or with the sleeve tool; edit product by product on the Catalogue. The variable names the file the first fill read.
Sleeve librarysrc\var\sleeves.db SCENARIO_SLEEVES_DBImport a file with the sleeve tool, or edit sleeve by sleeve in the console.
Funding split, overlay rulesThe same sleeves.db— The console only. A sleeve import does not touch them.
Fee cardThe same sleeves.dbSCENARIO_FEES_SOURCE The Repository's Fees tab: edit, or import a card file. See the fee card.
Proposals and account requestssrc\var\proposals.db SCENARIO_REGISTER_DBNever re-seeded. Nothing below touches it.

The order matters, because each layer checks the one before it: fee card → products → sleeves. A product must name a fee group the fee card knows, and a sleeve may only hold products the catalogue knows.

Keep the working files outside the project

Use a folder of its own, such as H:\pt-seed, for exports, new files and backups, the same way the updates live in H:\pt-update. Nothing you prepare then ends up in the project's own folders.

One-time setup: a run configuration for the sleeve tool

Everything below is done by one small program, the sleeve tool (cyrus_pmg.pmgService.scenario.sleeveTools). It must see the same settings as the service: the same product file, the same database and the same portfolio extract. The simplest way to guarantee that is to copy the service's own run configuration in PyCharm. The same tool loads product files too, so a whole re-seed can be done from here.

Copy the service's configuration

In PyCharm open Run → Edit Configurations…, select isgPMGService and press Copy Configuration (the icon of two pages, or Ctrl+D). Name the copy Sleeve tools.

Point it at the sleeve tool

Beside the script field there is a drop-down that reads Script path; change it to Module name and type cyrus_pmg.pmgService.scenario.sleeveTools. In Parameters type --census. Leave the working directory and the environment variables exactly as they were copied. Press OK.

Run it once to see what you have

Choose Sleeve tools in the run drop-down at the top right and press the green triangle. The census prints in the Run window. It is read-only, and it is safe to run at any time, with the service running or not.

The census is the first thing to read and the last thing to check. Its top lines tell you where everything is:

  PMG Multi-Asset Portfolio     27 sleeves

  • store is the sleeve database the tool is using. Back up this file.
  • catalogue is the product catalogue in that same store: its version (one more for every change), how many live products it holds, when it was last edited and by whom, and the file it was first filled from. seed means the first fill, not a person.
  • sleeves counts every edition, a sleeve's fallback included. labelled edition(s) with rules counts only the editions that carry rules.
  • Anything wrong is listed underneath, under BROKEN or NOT IN THE CATALOGUE. The run then ends with exit code 1 instead of 0.

To run anything else, edit the configuration's Parameters, for example to --export H:\pt-seed\library.csv, run it, and set it back to --census afterwards. Each run does one thing.

Re-seeding the product catalogue

The catalogue is kept in the database now, beside the sleeves. The update filled it, once, from the product file the service was set to read, and reported it:

== The product catalogue: 73 products in the database (first loaded from products.csv)

From then on a re-seed is an import. The tool compares your file with the catalogue, shows you every product it would add, change, bring back or leave out, and changes nothing until you apply it. A file with any wrong row is refused whole, so it never half-loads. Every product an import changes gets a new version recorded with your name, the time and the file name, so the re-seed can be read back product by product.

The columns

Row one holds the headers; the tool finds columns by their names, so the order is free. A row whose first cell is empty is skipped. The file you download from the Catalogue has exactly these columns, so the easiest file to edit is that one.

The file you download also ends with BaseCurrency: All on every row until a product has values of its own in a currency.

On an import, the six describing columns (AssetClass to ExposureCurrency) must all be filled, a Category the library does not know is refused, and a ProductCost of 10 or more or a DistributionYield of 50 or more is refused as a figure typed in the wrong unit (45 for 0.45).

Steps, in the Repository

Download what is there now

Open Repository → Catalogue and press Download the product file. Save it to H:\pt-seed twice: once as the backup (products-2026-10-16.csv) and once as the file you will edit (products-new.csv).

Make your changes in Excel

To add a product, add a row. To change one, edit its cells but keep its ProductId. To take one out, delete its row; the import will ask whether to withdraw it. A product a sleeve holds cannot be withdrawn, so take it out of those sleeves first (see the sleeves), or leave it in.

Save with File → Save As → CSV UTF-8 (Comma delimited). An .xlsx also works, provided the products are on its first sheet or on a sheet called products.

Import it and read the preview

Back on the Catalogue, press Import a file and choose products-new.csv. Nothing changes yet. The preview lists what the file would do:

1 new       GS Access India Equity ETF
1 changed   GSAM Short Duration SMA
              · Product cost 0.22 → 0.24

A product in the catalogue that the file leaves out is listed under in the catalogue but not in the file - kept unless ticked. Tick Withdraw beside it to take it out. One that a sleeve holds has no tick box and says in 3 sleeves, so it stays.

Apply it

Type a note if you like (where the file came from), and press Apply the import. The toolbar says what happened, for example Imported products-new.csv: 1 added, 1 changed, 0 withdrawn · the catalogue is version 2. New products can be placed in sleeves straight away, on the Sleeves tab.

If the file itself is wrong, the preview is refused and names the row and the problem:

products-bad.csv: row 5 (gs-us-corporate-bond-fund): The fee group 'Core active' is not on the fee card: it is spelled Core Active.
products-new.csv: row 75: the ProductId gs-access-em-equity-etf is already on row 22 - each product appears once.

Undoing it

Import the backup you downloaded first. Every product the re-seed changed goes back to its earlier values as a new version, and the products the re-seed added are listed as not in the file: tick them to withdraw them. For one product, open its card on the Catalogue, press Show every version and Restore this version.

Adding the categories

A product has had a Category of its own since the update that brought it (the sleeve database's schema 9). The Catalogue groups products by it. That update adds the column with every product's category blank, and until a product has one the Catalogue groups it by the sleeves that hold it, as before, or under No category if no sleeve does. Nothing a PWA sees or a proposal prints depends on it.

Run the update first

The census should say schema v9 or later. A file imported before the update loads its other columns but drops the categories without saying so.

Add the column to your product file

Put a column headed Category (or Catagory, or Group) anywhere in the file and give every product its category, spelled as in the table above. A product can have one category only. Keep each ProductId as it is.

Import it and read the preview

Use Import a file on the Catalogue, or the sleeve tool's --products-import. The preview shows each product's category as a change:

Check the Catalogue

Press Ctrl+F5 and open Repository → Catalogue. Every product sits in its own category's band, and No category holds only the products you left blank. One product can also be given or changed a category on its own: open its card, press Edit and choose from Category.

Products by base currency

A product is one product in every base currency, but each currency can list it under its own ticker, give it its own minimum, its own exposure currency and its own issue currency: a share class hedged to each base currency, say. It can also be left out of a currency altogether. A scenario shows the ticker and exposure for its own currency in the implementation table, the custom builders, the sheet, the deck and the saved proposal, and checks a position against that currency's minimum.

One row per currency

Give the product a row for each base currency it differs in, all with the same ProductId, and say which currency each row is for in BaseCurrency. A name may end in its row's currency, GS Green Bond Fund (GBP): the catalogue shows it as GS Green Bond Fund. Only Ticker, MinimumInvestment, ExposureCurrency and IssueCurrency may differ between a product's rows; everything else must be the same on every row.

gs-access-treasury-0-1-etf,GS Access Treasury 0-1 ETF (CHF),GBIL SW,…,CHF,…,,CHF

All, or the currencies it is offered in

With an All row, the product is offered in every currency: All is what a currency without a row of its own reads. With no All row it is offered only in the currencies it has rows for. Above, the green bond fund is not offered in CHF. A CHF proposal whose sleeve holds it shows not in CHF on the product's row, and the download stays blocked until the sleeve is changed.

A row is the product whole

A currency's row says everything about the product in that currency, so a blank there means none: a blank minimum on the GBP row is no minimum in GBP, even when the All row has one. A minimum is in US dollars on every row: 250000 on the GBP row is a $250,000 minimum for a GBP proposal, which is in dollars too.

Re-seeding the sleeve library

A sleeve file is loaded with the sleeve tool's --import. The import checks every row the same way the console checks a save, and loads nothing if any row fails, so the library is never left half-changed. Every change it makes is recorded in each sleeve's history, and nothing is destroyed.

The vocabulary

WordMeaning
VariantThe implementation types the sleeve is offered under: PMG Multi-Asset Portfolio, PMG ESG, US Onshore or Irish Onshore; several separated by |; or All for every type. Several make one shared sleeve. The PWA chooses the type in step 2.
CategoryOne of the seven: Investment Grade Fixed Income, Hybrid Fixed Income, Other Fixed Income, Public Equity, Hedge Funds, Private Equity & Other Private Assets, Asset Allocation Strategies.
SleeveThe name the PWA picks, e.g. Global Equity Core.
EditionA version of the same sleeve for particular portfolios. Left blank it is the fallback, the version everyone gets unless a labelled edition claims their portfolio. Filled in, e.g. GBP, it is a labelled edition and needs at least one rule.
RuleWhich strategic portfolios a labelled edition is for, by currency, risk level and allocation type.

The two files

The sleeves file has one row per product in an edition:

Variant,Category,Sleeve,Edition,ProductId,Weight

Weight is a fraction, so 60% is 0.6. In Excel you may format the column as a percentage and type 60%, which is the same value. Each edition's weights must total exactly 100%, and a product may appear only once in an edition.

The rules file has one row per rule, and sits beside the sleeves file with .rules added to its name (library.csv → library.rules.csv):

Variant,Category,Sleeve,Edition,Currency,RiskLevel,AllocationType

A library with no labelled editions needs no rules file. An Excel workbook can carry both instead: a sheet named Sleeves and a sheet named Rules.

Add to the library, or replace it

ParametersWhat happensUse it when
--import FILEAdds and updates. An edition in the file with the same variant, category, sleeve and edition label as a live one replaces it as a new revision, keeping its identity and history. Everything not in the file stays as it is.You are changing or adding some sleeves.
--import FILE --replaceReplaces. Every live sleeve is archived first, each with a final revision recording who and when, and then the file is loaded as the whole library, all in one step.You want the library to be exactly the file.
A replace loads exactly what the file holds, even if that is nothing

An empty or half-finished file with --replace archives the whole library and loads what little is there. The import cannot know you meant more. Run the census straight after; if anything is missing, see undoing a re-seed.

Steps

Export what is there now

Set the Sleeve tools parameters to --export H:\pt-seed\library.csv and run. It writes library.csv, and library.rules.csv beside it if any edition has rules. This is the starting point for your edits, in exactly the right format.

Keep a backup

Copy the export to H:\pt-seed\library-2026-10-15.csv (and its rules file the same way). Then stop isgPMGService and copy the store file (src\var\sleeves.db) to H:\pt-seed\sleeves-2026-10-15.db. Copy the database only while the service is stopped.

Edit in Excel

Open library.csv, change, add or delete rows, and save it as CSV UTF-8. If you add labelled editions, add their rules to library.rules.csv. Create that file with the header line above if the export did not write one. The next section shows how to write editions and rules.

Import

Set the parameters to --import H:\pt-seed\library.csv --replace (or without --replace to add and update only) and run. Success reads:

replaced the library with 108 editions from H:\pt-seed\library.csv (with 5 rule(s))

A refusal names the problem, and nothing has changed:

REFUSED (weights): Weights sum to 90.00%; a sleeve must sum to exactly 100%.
nothing was written

Fix the file and run again. The table of refusals lists the usual ones.

Check, then start the service

Set the parameters back to --census and run. Look for no BROKEN list, the counts per type you expect, and an exit code of 0. Then start isgPMGService, dashboardFrontend and optimizationService, and press Ctrl+F5 on the page.

Editions, rules and types: how to seed each kind

All the examples below were loaded through the import and checked with the census before this guide was written. Each one is a set of rows to add to library.csv and, where it has rules, library.rules.csv.

How a rule reads

  • Within a row, every filled cell must match (AND). A blank cell means any value.
  • Several values in one cell are separated by |, and any of them matches (OR): LowVol|Conservative.
  • Several rows for one edition mean the edition applies if any row matches (OR).
  • A rule must fill at least one cell. A rule that matches everything is what the fallback is for.
CellValues it accepts
CurrencyUSD GBP CHF EUR
RiskLevelLowVol Conservative ConsMod Moderate ModAgg Agg Higher Risk All Equity
AllocationTypeFull Core ex-Alts ex-HFs NA (NA is the all-equity portfolio, which has no allocation type)

The values are written exactly as above, capitals included. Only values present in the current portfolio extract are accepted.

Which edition a portfolio gets

  1. If exactly one labelled edition's rules match the portfolio, that edition is served.
  2. If none match, the fallback is served.
  3. If none match and there is no fallback, the sleeve is not offered for that portfolio at all.
  4. Two labelled editions of one sleeve may never claim the same portfolio. The import refuses it, naming the portfolios they share.

The PWA never sees which edition applied: they pick the sleeve by name, and the tool serves the right products.

1. A plain sleeve: one fallback, no rules

PMG Multi-Asset Portfolio,Public Equity,Global Equity Core,,gs-us-equity-insights-fund,0.6
PMG Multi-Asset Portfolio,Public Equity,Global Equity Core,,northbrook-intl-equity,0.3
PMG Multi-Asset Portfolio,Public Equity,Global Equity Core,,gs-emerging-markets-equity,0.1

The Edition cell is empty, so these rows are the fallback. No rules file entry is needed.

2. A different line-up for one currency

GBP portfolios get two different products; everyone else keeps the fallback above.

PMG Multi-Asset Portfolio,Public Equity,Global Equity Core,GBP,gs-access-world-equity-ucits,0.7
PMG Multi-Asset Portfolio,Public Equity,Global Equity Core,GBP,gs-access-em-equity-etf,0.3

and in the rules file:

PMG Multi-Asset Portfolio,Public Equity,Global Equity Core,GBP,GBP,,

3. Several risk levels in one currency

The cautious EUR portfolios, and no others, get a single passive product.

PMG Multi-Asset Portfolio,Public Equity,Global Equity Core,Cautious EUR,gs-access-intl-equity-etf,1
PMG Multi-Asset Portfolio,Public Equity,Global Equity Core,Cautious EUR,EUR,LowVol|Conservative|ConsMod,

4. Two unrelated groups: two rule rows

One edition for growth-minded USD portfolios and for CHF Full portfolios. These can't be said in one row, so the edition gets two.

PMG Multi-Asset Portfolio,Public Equity,Global Equity Core,USD growth / CHF Full,gs-us-equity-insights-fund,0.5

PMG Multi-Asset Portfolio,Public Equity,Global Equity Core,USD growth / CHF Full,CHF,,Full

Examples 1 to 4 together make one sleeve, Global Equity Core, with a fallback and three labelled editions that never claim the same portfolio.

5. A sleeve offered only to some portfolios

Leave out the fallback and give the sleeve only a labelled edition. It then appears only where that edition's rules match; here, GBP portfolios.

PMG Multi-Asset Portfolio,Public Equity,UK Equity Income,GBP only,gs-access-world-equity-ucits,1
PMG Multi-Asset Portfolio,Public Equity,UK Equity Income,GBP only,GBP,,

6. The same name under another type, with its own products

To offer Global Equity Core to ESG proposals with different products, give it rows under PMG ESG alone. That is a separate sleeve with the same name: its editions and rules are its own, and an edit to the Multi-Asset one leaves it as it is.

PMG ESG,Public Equity,Global Equity Core,,gs-access-esg-us-equity-etf,0.5
PMG ESG,Public Equity,Global Equity Core,,gs-esg-international-equity,0.5
The four types are fixed in the tool

A file can use only PMG Multi-Asset Portfolio, PMG ESG, US Onshore and Irish Onshore. A new implementation type is a change to the tool itself, not to the data.

7. One sleeve shared by several types

A sleeve that is the same everywhere is written once, with every type it is for in Variant: All, or the types separated by |. It is then one sleeve: one set of products and one history, so an edit made in the console under any of its types is what all of them get.

All,Public Equity,Global Equity Passive,,gs-access-intl-equity-etf,0.6
All,Public Equity,Global Equity Passive,,gs-access-em-equity-etf,0.4
PMG Multi-Asset Portfolio|PMG ESG,Public Equity,Developed Equity Core,,gs-us-equity-insights-fund,1

Each type still has its own list: a type may not have a sleeve of the same name of its own as well. Adding one is refused, and nothing is written:

REFUSED (name): A sleeve named Global Equity Passive already exists in Public Equity under PMG ESG. To offer it for particular portfolios, add an edition to it instead.
nothing was written

An export writes a shared sleeve the same way (All, or the types with |), and importing it again changes that same sleeve. The census counts it under each of its types and says how many there are:

           6 shared by several types, counted under each

In the console

A shared sleeve shows a Shared chip, and its page lists the types under Offered under. + Share with offers it under another type too. When one type needs it to differ, choose the type under Make one differ and press Give it its own copy: that type gets a separate copy holding the same products, and the rest stay shared. Stop offering it there takes a type away. None of these is a new version of the sleeve, and each is on the Activity tab. + New sleeve with several types ticked makes one shared sleeve.

9. The two fixed categories

Hybrid Fixed Income and Asset Allocation Strategies hold exactly one sleeve per type, which the overlays attach automatically. Give each type one sleeve in each, with no labelled editions; one sleeve shared by every type (All) does for all four. A replace that leaves them out is accepted by the import, but the census then reports each missing one and ends with exit code 1, and the overlays have nothing to attach. Always keep them in the file.

Naming

  • Names and labels are tidied when loaded: spaces at the ends are removed, and doubled spaces become one.
  • Names that differ only in capitals or spacing count as the same name.
  • Label editions for the person reading the list, e.g. GBP or Cautious EUR. The word fallback is reserved.

Watch for a stray rules file

If the import finds no library.rules.csv beside your file, it looks for a sleeveRules.csv in the same folder and uses that. Keep H:\pt-seed free of old rules files, or name yours to match.

Undoing a re-seed

  • Quickest: import the export you took first, with --replace: --import H:\pt-seed\library-2026-10-15.csv --replace. The library is back as it was, and the detour stays on the record.
  • One sleeve: in the console, open the sleeve's history and restore it, or restore it from the Archive.
  • Everything, exactly: stop the service and copy sleeves-2026-10-15.db back over src\var\sleeves.db. This also brings back the funding split and overlay rules as they were at the backup.

What not to do

Don't delete sleeves.db to start again

A new, empty database seeds itself once from a seed file, and the tool's own instructions mention it. On a working system it costs far more than it saves:

  • every sleeve's history and the archive go;
  • the funding split and the overlay rules return to their starting values;
  • sleeves get new numbers, so the proposals already on record no longer point at the sleeves they were built from;
  • if the seed file is missing, the new database starts empty and stays empty: it never tries to seed again;
  • the product catalogue and the fee card are filled again from their files, losing every edit and import since, and their histories.

An import with --replace gives the same clean library without any of that.

The fee card

The fee card is kept in the database as well, and changed on the Repository's Fees tab: rates, fee groups and tiers, each change saved as a new version with a note. If new products need a fee group the card does not have, add it there first (Edit the card, then Add the group on the new-group card at the end, and paste its rates from Excel into its card), then import the products. A fee card file is imported on the same tab with Import a file, which shows every rate it would move before anything changes; Download the card writes the card in force as a file.

Quick reference

Sleeve tools parameters

--census
What is there, and what is broken. Read-only.
--export FILE
Write the live library to FILE and FILE's .rules sibling.
--import FILE
Add and update from FILE; everything else stays.
--import FILE --replace
Archive the library and load FILE as the whole of it.
--archived
List archived sleeves.
--history ID
Every revision of one sleeve (the number in square brackets in a listing).
--activity
The 40 latest changes across the repository: sleeves, products, the fee card, overlay rules and the funding split.
--products-export FILE
Write the product catalogue to FILE.
--products-import FILE
Add and update products from FILE; products it leaves out stay.
--products-import FILE --withdraw-missing
And withdraw the products FILE leaves out.
--product-history ID
Every version of one product.

A re-seed in order

1. Census
Note the store path and the catalogue's version.
2. Backups
--products-export, the sleeve --export, and a copy of sleeves.db with the service stopped. That one copy holds the catalogue and the fee card too.
3. Fee groups
Only if new products need one: add it on the Fees tab first.
4. Products
--products-import the edited file, or Import a file on the Catalogue.
5. Sleeves
Edit the export, import, census.
6. Start
The three services, then Ctrl+F5.
